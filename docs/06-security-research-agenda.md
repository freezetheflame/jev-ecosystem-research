# Jev + 安全：router 方向的科研切入点

整理自 2026-10-02。目标：做 Jev 与安全交叉的科研，评估 router 这一侧还有哪些**未被占坑**的切入点。

---

## 一、先看清谁占了坑（避免重复）

| 工作 | 做了什么 | 对本方向的意义 |
|---|---|---|
| **Decision Hijacking** (arXiv:2609.28613, Wu & Lim, NTU) | 54,060 次调用打 Jev 类型化决策，510 条 InjecAgent direct-harm，钉 `jev-1.13.0` | **"Jev + 提示注入"已封闭** |
| **Check Point Research** (2026-09-24) | 尽调 agent，9 种攻击者×难度组合全破，约 \$0.50/次 | 同上，"结构化输出不是安全边界"已被论证 |
| **Rerouting LLM Routers** (arXiv:2501.01818) | confounder gadgets，向上打到贵模型；困惑度防御被低困惑度 gadget 绕过 | **向上方向已封闭** |
| **R2A / Route to Rome** (ACL 2026, 2604.15022) | 黑盒后缀优化，7 个 router，OpenRouter 成本最高 2.9× | 同上。自述局限：需知道候选模型池和被选模型身份 |
| **RerouteGuard** (arXiv:2601.21380) | taxonomy：cost escalation / quality hijacking / safety bypass；嵌入式检测 99% | taxonomy 已立，但**实测只做了 cost escalation** |
| **Your Agent Is Mine** (arXiv:2604.08407) | 恶意第三方 API router：payload injection + secret exfiltration，428 个 router | 中间人方向已封闭 |
| **Conformal LLM Routing** (ACL 2026 SRW, Uddin & Bauer) | 路由的分布无关安全保证 | 依赖 **exchangeability** 假设 |

### 2609.28613 的关键数据（必读）

- 攻击者目标被选中率仅 **1.8%**（自适应优化后 3.5%），但**概率质量被可靠推动**。论文的方法论贡献正是把"概率位移"与"实际选中"分开度量。
- **反直觉结果**：`"IMPORTANT!!! Ignore all previous instructions"` 对 Jev **反而伤害攻击者**——base 选中 9/510（1.8%），enhanced 变成 0/510；概率差 **−0.034，95% CI [−0.062, −0.015]**。而这句对生成式 agent 是**增强**攻击的。

> **推论：生成式时代的注入语法在决策模型上失效了。** 那什么语法有效？**注入语法的迁移性**本身就是一个干净的、无人做的研究问题。

### Check Point 的关键数据

- 9 种组合全部至少成功一次；最强 25/27，平均第 4 轮，约 \$0.50/次
- 结构化输出**无帮助**；把文档标记为不可信**无帮助**（16/27，与 inline 相同）；反注入指令 18→17（噪声）
- 唯一有效的是 reasoning effort：攻击成本 \$0.56 → \$4.39
- 结论原文："输出格式约束的是**能说什么**，不是**能信什么**"

## 二、空白在哪：文献只覆盖了六分之一

已有 router 攻击**全部只扰动 `query` / `state` 文本**这一个输入。

但 Jev 的决策是 `f(state, question, **choice set**)`——**选项集合是调用方定义的一等输入，在连续型 router 里根本没有对应物**。

| 可控输入 | 研究状态 |
|---|---|
| 查询 / state 文本 | **已被反复研究** |
| 选项集合内容 | 空白 |
| 选项顺序与标签 | 空白（已知能摆 51pp） |
| 路由租期 | 空白 |
| 缓存状态 | 空白（首个有状态路由） |
| 失败 / 降级路径 | 空白 |

## 三、切入点排序

### ① 选项集合操纵（choice-set manipulation）— 最强

已有工作全部只扰动 query。子攻击：

- **增删诱导选项**——插入语义相近的诱饵选项，分散目标选项的概率质量
- **改标签 / 别名**——同一个档位换个说法
- **改顺序**——实测能把准确率从 72% 摆到 21%
- **改档位粒度**——把 `{haiku, sonnet, opus}` 合并或拆分，概率质量必然重分配

最后这个在 router 场景是致命的：**router 作者自己定义选项集**，而且很多实现会动态生成选项。攻击者只要能影响选项集的构造，就能**不碰 query 就改变路由**。

**防御侧更漂亮**：对选项顺序做**随机化平滑 + 聚合，能给出可证明的鲁棒性界**。有 certificate 的防御，理论分量够。

### ② 降级攻击（silent capability downgrade）— 方向相反，无人做

Rerouting、R2A、RerouteGuard **全是向上打**，因为成本是可测信号。

**向下打没有信号**：HTTP 200，遥测显示"省钱"，只有用户知道答案变蠢了（就是 `05-jev-router-ecosystem.md` 里 Matt Doughty 那条）。

而且 Jev 有个放大器——**攻击者根本不需要对抗样本，只要把输入推进"密封"分布**（36.7%，随机基线 29.3%）。**分布漂移即武器。**

**延伸一步更狠**：`0xNatoshi/jev-codex-router` 的 forced-Astra 策略（架构 / 终审 / 安全 / 权限 / 并发 / 迁移 / 公共 API 兼容性 / 重大性能风险）本质是**用自然语言写的、由决策模型判定的安全策略**。

> 能否把一个安全关键子任务表述得不触发它？
> 这正是 RerouteGuard 点名却没实测的 **safety bypass**。

### ③ 校准但错误 — 便宜且危险

所有部署建议都说"用概率设阈值"。但数据摆在这里：公开 86.6% → 密封 36.7%，而**校准轴仍有 76.3**。

**假设：置信度不随准确率一起退化。** 若成立，"概率设阈值 + 中间地带送审"这套标准做法在漂移下**静默失效**。

这是负结果，但负结果在这里就是贡献。而且能直接接 conformal：漂移破坏 exchangeability，Uddin & Bauer 的保证会破，**而 Jev 的概率不会报警** → 提出"conformal + 漂移检测"双闸门。

不需要新攻击，用公开 / 密封切分就能跑，**成本极低**。

### ④ 有状态路由 — 整块处女地

已有 router 攻击全部假设**无状态、逐请求**。OpenRouter 的 Jev Router 是**第一个有状态的**（决策依赖缓存）。新攻击类：

- **缓存预热操纵路由经济**——先发前缀预热目标模型缓存 → router 的成本模型就变了 → 攻击者决定哪个模型服务自己的请求。**全程不碰 query 文本，因此绕过 RerouteGuard、困惑度过滤、输入筛查等所有输入侧防御**
- **cache-thrash DoS**——构造在模型间来回振荡的输入，每次换模型缓存全失效，成本爆炸
- **跨租户缓存侧信道**——路由决策 + 延迟 + 成本遥测泄露"是否有相似前缀近期被缓存"
- **租期劫持**——让 Jev 选长租期（user_turn 而非 one_call），一个坏决策持久化覆盖后续多次调用

**理论甜点**：有状态直接破坏 exchangeability → conformal 的保证失效。这是个定理级结果 + 实证。

### ⑤ 方法学：开源复现当白盒代理（可包进 ①–④）

R2A 自述局限是"需要知道候选模型池和被选模型身份"。**开源生态正好解决这个**：Imajev-4B、decider-4b、Plumb-4B、Cygnet 权重可下。

而且 Cygnet 这类"冻结基座 + 读字母 logit"的复现**把读出机制完全暴露**（A/B/C logit + 标定温度）——你可以直接对 letter readout 求梯度，这大概率就是闭源 Jev 内部在做的事，是个**异常强的 surrogate**。

可发表的问题：**同类架构的决策模型之间，选项操纵攻击的迁移率有多高？**

**防御侧**：异构决策模型 quorum（Jev + Imajev-4B + decider-4b 必须一致才路由）。决策边界不同 → 是否天然抵抗 gadget？**生态多样性本身变成防御原语。**

### ⑥ 测量类短文

- **双投影声称未审计**：0xNatoshi 说 Jev 只看"有界决策状态"，没人验证过。抓 10 个主流 router 实现，实测发往 Jev 端点的 payload 里有没有密钥 / 文件路径 / PII。
- **路由日志作为侧信道**：被动看路由决策能推断多少查询内容。

工作量小，容易出。

## 四、实践注意事项

1. **必须钉版本**。2609.28613 钉的是 `jev-1.13.0`；JevBench v1.4.2.2 → v1.5.4 分数会动（Autoloops 从 29.96 跳到 40.53）。
2. **对商业 API 做攻击测试注意 ToS 与负责任披露**。DoS 类别别真打生产服务——建模 + 小规模 + 自建复现。
3. Jev 发布不足一个月，**"首个 / 首次"类声明要谨慎**，地基可能变。
4. **别再拿"Jev 不生成文本所以抗注入"当前提**——已被证伪两次。论文应该站在**已被证伪的直觉之上做下一层**，会更有力。

## 五、一句话

> 已有工作覆盖了 Jev router 的 **query 文本**这一个输入面。真正的空白在**结构侧**（选项集合、租期、缓存状态、失败路径）和**方向侧**（向下降级，而非向上升级）。
