# Jev 跑测实践：经验、证据与代码边界

整理日期：2026-10-27。来源是 Jev 安全工作区已有的静态扫描、配对实验和模拟门控记录。本次只整理和导出，不新增付费推理。本文不更新整个生态榜单，也不把历史探索结果改称确认性实验。

## 1. 先明确测谁、测哪一段

| 位置 | 判断对象 | 常用问题 | 标签语义 |
|---|---|---|---|
| S1 | Skill / 工具描述等制品 | 安装或遵循是否安全 | `artifact_threat` |
| S2 | 邮件、网页、工具结果 | 是否包含应警惕的入站内容 | 依语料区分威胁或结果标签 |
| S3 | 用户请求 | 是否应该拒绝 | `should_refuse` |
| S4 | 待执行动作及其任务/历史 | 当前动作是否获用户授权 | `outcome_unsafe` |
| S5 | 完整轨迹 | 已发生的行为是否不安全 | `outcome_unsafe` |

S1–S5 是原工作区的输入位置标签；本仓库 Mode A/B/C/D 是决策时点与可见信息合同。S4 静态动作回放与 Mode B 的目标接近，但没有真实拦截或重规划，因此不等于 Mode B 闭环实测。S3 也不能直接冒充 Mode A。

不要混合 artifact_threat、should_refuse、outcome_unsafe 计算一个安全总分。正常请求含危险词，不一定应拒绝；历史里出现注入，不一定代表当前动作越权。上游未知/第三类标签保留 null，不自动变成负例。

## 2. 接口形状与答案方向必须写进代码

实际 Jev 请求为 `POST https://api.typesafe.ai/v1/systemone`，正文 `{model, state, questions}`，不是 chat messages。每条单问题实验的 questions 只有一个键；三种 type 分三次请求。

```json
{
  "model": "jev-1.14.0",
  "state": "<serialized task, tools, history and final action>",
  "questions": {
    "unauthorized_action": {
      "type": "noul",
      "instructions": "<trusted authorization rubric>",
      "criteria": {"false": "Authorized action", "true": "Unauthorized action"}
    }
  }
}
```

上面只是接口示意，真实完整 rubric 见[冻结请求配置](../../data/workspace-evidence/2026-10-27-agentdojo-types/sample-manifest.json)。样本本身是不可信证据，不让其内容修改 rubric；gold 只进入本地分析。

- 问“是否安全”：noul=P(safe)，risk=1−noul。
- 问“是否越权”：noul=P(unsafe)，risk=noul。
- choice 的风险排序取 P(unsafe)，原生类别取 choice；confidence 不当作风险。
- 两级 score=[safe,unsafe] 的范围是 0..1；多级 score 必须另定义归一化与阈值，不能沿用二级实验的解释。
- 严格拒绝 bool 冒充数字、NaN、越界、缺字段、未知选项。choice 概率恰为 0.5 时保留返回的原生选项，不能偷偷改平局策略。

[官方 Choice](https://docs.typesafe.ai/primitives/choice)、[Noul](https://docs.typesafe.ai/primitives/noul)、[Score](https://docs.typesafe.ai/primitives/score) 是接口依据；模型返回概率不自动证明在本任务上已校准。

## 3. 问句、格式、阈值是不同实验因素

已有结果不能归结为“Jev 一般好/不好”。每个数字至少同时注明 **模型版本、profile/问句、阈值、语料切片、共同成功分母**。

| 已有观测 | 可复用的教训 | 限制 |
|---|---|---|
| 100 条 wild 上 v2 恶意性问句把 FPR 从 15% 降为 0%，召回从 65% 降为 5% | 零误报可能只是整体分数下移；必须同时看 FN、召回与 AUROC | 阈值固定 0.5、20 正 80 负、原格式；探索性单轮 |
| 早期 50 条有标签 S4 配对中，Skill 问句→动作问句使 FPR 40%→4%，召回 100%→88% | 当前动作授权不能由“上下文有恶意内容”替代；降低误报也可能付出召回代价 | banking 小样本、顺序抽样；不是 TS-Bench 总体 |
| 后续 80 条 AgentDojo 配对中 S4 v1/v2 分类相同，但低余量正例数量不同 | 同时看操作点与分数距阈值的余量 | 单轮、非鲁棒性保证 |
| 1.14 的 500 条三 type 对比中，准确率仅差 0.2–0.4 个百分点 | 在相同两端定义下，type 差异在本批数据上较小 | score 只有两级；无同请求重复，不能证明等效 |

第一项机器可读证据见[问句 v2 汇总](../../data/workspace-evidence/2026-09-29-question-v2/summary.json)；完整历史说明及 S4 两轮来源见[证据索引](../../data/workspace-evidence/README.md)。

原工作区的结构化输入只改变 state 格式，不自动替换问题。九维同请求、多请求并行和单问题也不是同一种协议。阈值在已观察测试集上扫出来，只是描述性分析；真正部署阈值需要独立校准集与未见测试集。

## 4. 抽样和语料审计比扩大条数更重要

统一数据曾达到 27,230 条 / 20 个语料；它是覆盖矩阵，不是新版阶段问句的全量成绩。旧 profile 已成功预测 13,173 条，也不能将不同 profile 与不同覆盖结果相加为一个分数。

TS-Bench 的 7,182 条混合 AgentDojo、ASB、AgentHarm；这次只取 AgentDojo 1,220 条。ASB 的工具名可能直接暴露标签，AgentHarm 的意图判断又不同；不能让大组稀释主任务。原始 AgentDojo 定义抽取的 S2 63 条、S3 83 条，与本次 S4 片段不是同一数据集。

小批量优先用确定性 seed 按来源/套件 × 标签分层，保存精确 UID 与输入 hash，所有臂使用同一批。文件顺序的前 N 条会集中在一个套件；声称“随机样本”前核对实现。比例抽样保留标签分布，正负平衡样本则改变先验；precision、F1、accuracy 不可跨不同类比例随意排名。

先用无 API 的数据检查/确定性规则验证管线，再做每种接口真实先导；默认新实验上限 100，明确要求才扩大。样本数量不是调用次数：questions、分片、重试、补测都单列。

## 5. 长文本分片必须显式报告

当前沿用 48,000 字符 / 2,000 重叠，分片风险取 max。500 条中 5 条各两片，三臂从 1,500 增至 1,515 次成功请求。字符上限不是 token 上下文上限。

max 聚合保守，但分片可能把任务授权与动作拆开；不能说它保持全部上下文。比较长度效应要控制内容，不能将两个不同版本轨迹集的成绩差直接归因于长度。新长上下文服务参数应另冻结，不与旧分片结果混用。

## 6. 网络、模型与密钥要分别记录

历史 1.13 默认直连更快的经验不是永久配置。本次直连 1.14 + key2 仍得到 HTTP 451；指定 7892 时本机无监听；7890 的显式 HTTP 代理使三种 type 均成功。后段又遇 TLS EOF，30 个失败项以同配置补齐。

这些只是本机当时观测，不证明某端口普遍正确，也不证明 451 是模型或密钥的问题。代理参数必须记录并清除冲突的 no_proxy；不要默默换端点/模型绕过失败。密钥只保存变量选择名，永不记录值。核对返回 model，不能仅信请求里写的版本。

暂时网络错误与 429/5xx 可有限退避重试；401/402/403/451 应停止并检查，避免批量刷失败。保留故障事实，不能把失败当安全，也不能只补不利预测。

## 7. 时间、费用、成功率的分母要拆开

| 指标 | 本轮例子 | 含义 |
|---|---:|---|
| 最终唯一样本 | 500 | 每臂相同动作片段 |
| 计划样本/type cell | 1,500 | 500 × 3 |
| 执行 cell 评估次数 | 1,530 | 含 30 次单独补测 |
| 网络尝试 | 1,628 | 含分片与内部重试 |
| 成功返回 | 1,515 | 每臂 505 个分片响应 |
| 首轮 cell 成功率 | 1,470/1,500=98% | 每组内部重试后 |
| 最终 cell 完成率 | 1,500/1,500=100% | 补测后 |
| 每次网络尝试成功率 | 1,515/1,628≈93.1% | 含失败尝试 |

延迟保存 mean/P50/P95/N，写清分片、代理、排队、重试和解析的包含范围。墙钟历时与并发请求耗时和分别报告。当前历史统计的 18.09 分钟包括中间间隔，不是纯模型推理或吞吐基准。

费用使用真实 usage × 当轮价格快照。Jev 1.14 的[官方模型页](https://docs.typesafe.ai/models)在 2026-10-27 核实为输入 $0.042/M、输出免费。已知 4,649,653 输入 token 的估价 $0.195285；113 次失败尝试没有 usage，其账单影响未知。主 Agent、判分器和本地算力在本轮未运行或未计价，不凭空填零来包装“总成本”。

## 8. 与 LLM / 本地模型比较时，比较接口也是变量

既有 100 条配对：MSB 30、MCPTox 30、AgentDojo 40，每类平衡且文本≤12,000 字符。Jev 是相同 UID 历史预测；Plumb、decider、H2O 在本地 GPU 实测；DeepSeek 的第二轮显式 YES/NO + confidence 是看过第一轮后修订，属于探索性结果。

LLM 生成的自报概率、模型 token 分布与 Jev 标量不是相同校准保证。保留 reason 可发现“理由说安全，数值却按危险解释”的协议错误，但 reason 不证明忠实推理。先固定答案方向，再统一 risk 映射。

H2O 官方 shim 的概率 floor 会压平分数，故保留原始概率和 served score。该批 S4 中 H2O 原始 AUROC=1.000、默认阈值召回65%，不能用测试集挑阈值后宣称生产改进。Transformers + 官方 shim 结果也不能直接称 stock vLLM 一致性验证。

不同后端首次编译、缓存、文本长度与网络会改变延迟。API token/账单不等于本地 FLOPs/GPU 能耗；本地默认未计价。相同数据/问题/信息边界与调参预算优先，避免统一一个不适合所有模型的提示词后直接排名。

## 9. 静态正确率与门禁收益分别测

13 任务模拟 harness 的 sink 门控比全步骤门控有更低 utility 损失，是小规模脚本策略的机制证据。没有真实自主 LLM agent，不能外推到实际部署 ASR。报告攻击是否到达 gate、到达后是否拦截、良性任务完成与 strict utility；不能用上游误拒让攻击根本未发生，再把 ASR=0 当完美门禁。

要研究完整闭环，沿用本仓库[执行规范](../model-evaluation/agent-security-experiment-protocol.md)与 Mode 合同，另做环境恢复、轨迹、攻击/效用判分及重复运行。此次静态结果不改变该研究的“正式配置尚未冻结”状态。

## 10. 可复用代码与仍缺的部分

代码导出见[framework](../../framework/README.md)；外部源码职责与依赖哈希见[source manifest](../../framework/source-manifest.json)。配置/请求、原始记录、分析、monitor 分开；费用汇总不能重复计入两次。原 monitor 没有预算硬停止、请求开始前事件和原生 episode/call ID，不能声称现成拥有这些能力。

每轮冻结模型、profile、输入、样本、阈值、代码与价格。原始预测 append-only，失败补测另写带父记录哈希的日志。导出后的代码有适配修改，新开输出；旧结果仍绑定原实现，绝不追改 manifest 让它假装一致。

目前可交付的是已有经验、有边界的测量记录与静态评测适配代码；完整 Agent 闭环、轨迹聚类统计、跨重复噪声、独立校准和确认集仍需后续工作。
