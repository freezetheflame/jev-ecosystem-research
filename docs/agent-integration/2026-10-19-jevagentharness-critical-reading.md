# JevAgentHarness 精读：控制委派的收益、证据与安全边界

日期：2026-10-19。材料类型：文献精读与方法评估。

论文为 [arXiv:2610.21412v1](https://arxiv.org/html/2610.21412v1)，2026-10-15 提交；代码核查固定在 [f2932199e1ef1d9f089b51d39430c87be0f560b5](https://github.com/JevAgentHarness/JevAgentHarness/tree/f2932199e1ef1d9f089b51d39430c87be0f560b5)。本轮阅读正文、相关附录和公开实现，独立核算作者发布的逐任务结果；没有重跑模型、训练或安全攻击。

使用 scientific-critical-thinking 的“问题—证据—设计—解释范围”框架。不对计算机系统论文机械使用临床 GRADE/RoB 评分，不给整篇论文编造质量总分。来源及 SHA-256 见[快照清单](../../data/jevagentharness-reading/2026-10-19/sources.json)。

## 1. 阅读结论

这篇工作最值得借鉴的是：把决策模型的评价单位从孤立问题推进到实际 Agent 的状态和完整任务，并通过独立校准与任务测试决定哪些控制权可以委派。

它支持在受测环境中研究和部署专用决策组件。它没有建立“低置信回退即可保证安全”“GRPO 是收益关键”“训练后的模型已具备普适控制能力”这些更强结论。作者自己报告了许多不支持原假设的结果；阅读时应当保留这些反证。

对本项目而言，闭环接入、一般性阈值迁移和简单审批已经是已有工作。剩余研究应明确落在攻击权限、授权语义、控制权转移和实际执行后果上。

## 2. 先固定研究对象和比较单位

论文的方法对象是“决策点 + 集成模式 + 阈值 + 决策模型”，而不是一个单独的 checkpoint。相同模型以不同方式接入，成本和风险可以相反。

论文区分三层评测：孤立问题、固定轨迹上的逐步判断、决策实际生效的闭环任务。前两层有助于定位问题，第三层才能观察错误改变后续状态的后果。见正文 §2–4。

精读时应给每个数字附上五项信息：

- 哪个 checkpoint，是否继续训练过。
- 哪个任务分布，是否与训练使用同一个生成器。
- 哪种集成模式，是否允许回退。
- 分母是状态、工具选择、任务还是重复尝试。
- 比较对象与运行硬件是否相同。

状态来自同一个任务时不能当作独立任务。公开 `stage2.json` 的逐任务数组可检查部分任务端点；它不能替代缺失的原始调用轨迹。

## 3. 方法怎样运作，公式究竟保证什么

可以把 Cascade 理解成：小模型先选候选项，满足接受条件时执行；否则由 LLM 决定。参数也可以拆成固定选项或从上下文复制的选择题。自由文本仍需要生成模型。

附录 A 的一般接受条件是比较两个决策者的条件正确率与调用成本。其理论依赖错误代价、条件校准和损失可加等假设；只有增加校准与 LLM 正确率不随置信度变化等条件，才得到简单单阈值形式。

**我的解释：**这是局部经济决策规则，不是对所有 Agent 状态的安全证明。若“取消错订单”和“读错一条无害记录”的损失不同，单一平均错误代价会丢失关键区别。多步后果又可能相互作用，局部最优也不能直接推出整段轨迹最优。

公开 `threshold_theory.py` 的说明明确承认，按“全部执行判断正确”与“至少一次错误”的任务组估计错误代价，是一种近似；困难任务同时更易出错和失败。不能将这一组间差异解释成一次错误的独立因果效应。要研究安全，应从同一状态干预动作后继续执行，或给操作定义明确的损失和权限约束。

另外，即使接受阈值内的决策都可靠，频繁询问小模型也有开销。阈值规则解决“已经询问后是否接受”，仍需任务级实验判断“这个决策点是否值得询问”。

## 4. 训练结果应怎样解释

训练不只是复制 Jev。目标中包含环境的标准答案，并在教师判断错误时使用标准答案；公开消融也比较了不同标签和数据构成。见 §5、附录 D.1–D.4。

据此不能把学生超过教师全部归因于软标签蒸馏，更不能假设换到真实安全任务仍能获得同等可靠的标准答案。安全标签需要独立定义授权者、对象、动作、范围和当前权限状态。

主要训练收益来自 SFT。作者没有观察到 GRPO 的可测额外收益，错误后状态的消融证据也有混合结果。若本项目使用其训练配方，应先做廉价 SFT 基线，再决定是否投入 RL；不能把训练流程中出现的每个环节都写成已证明有效。

还要区分 `AgentDecision-4B v1` 与继续加入公共工具数据的版本。后者可能提高公开题成绩，却降低某些闭环成绩。一个名字下的不同训练版本不能混用为同一条能力曲线。

## 5. 独立核算了什么

使用作者 `research/results/stage2/stage2.json` 中发布的逐任务二元端点，重新计算任务成功率、配对胜负和平均成本比。结果见[核算 JSON](../../data/jevagentharness-reading/2026-10-19/arithmetic_audit.json)，可用[脚本](../../data/jevagentharness-reading/2026-10-19/arithmetic_audit.py)重跑。

| 比较 | 配对任务 | 我方核算的成功率差 | 配对胜 / 负 | 我方核算的成本节省 |
|---|---:|---:|---:|---:|
| Jev 组合 vs LLM-only | 500 | -2.2pp | 2 / 13 | 40.73% |
| Jev 组合 vs 最佳单模块 | 500 | -2.6pp | 1 / 14 | 27.03% |
| 训练后组合 vs LLM-only | 500 | +0.6pp | 3 / 0 | 81.13% |

前两项未建立其注册的联合主张；第三项在该环境建立了非劣与成本节省。点估计落在非劣界内，不等于检验通过；需要保留估计不确定性和多重检验规则。见附录 E、G.1。这里没有重新实现作者的精确检验，也没有独立复核原始模型调用。

若 500 个独立同分布任务中没有观察到某种事件，单侧 95% 上界仍约为 0.60%。这是零事件的统计量级说明，不能据此对未见攻击分布声明风险上界。成功率检验的端点也不是越权执行率。

## 6. 证据中做得好的地方

### 比较单位与选择过程

作者采用配对任务、分开校准和测试、按任务聚类的分析，并把多项主检验作为明确的假设族处理。阶段一选模块，阶段二在新任务上检验组合，避免把模块分别可用等同于组合也可用。

### 报告反例

论文保留了组合未通过、迁移不成立、服务拥塞、训练环节无额外收益等结果。这些是理解适用边界的证据，不能只引用摘要中的最大节省。

### 检查生成器捷径

附录 D.10 加入模板和工具序列查表对照，承认不少同分布状态能由生成器规律解释。该对照比单纯换随机种子更能帮助解释高分。

### 记录复现边界

公开研究 README 指明若干测试会因原始运行记录、训练材料、私有云脚本或可选依赖缺失而跳过。因此“仓库有测试”与“外部研究者能复核所有论文结果”需要分开。

## 7. 最影响解释的限制，以及怎样补证据

| 观察位置 | 限制与影响 | 本项目可采用的补证据方式 |
|---|---|---|
| D.10、G.9 | 种子不重叠不能排除模板与规则共享；表面改名也不等于跨业务规则泛化 | 按规则、授权结构、工具语义和任务组合做留出，增加强规则基线 |
| D.1–D.4 | 标准答案、教师、回放数据与 SFT 同时变化，不能将所有增益归给一种训练机制 | 固定数据量和训练步数，分别去掉软标签、错误后状态与安全监督 |
| A、§2.1 | 平均错误代价和局部条件不足以表达攻击下的非对称损失 | 追踪实际受影响对象、动作后果和累计权限，使用共同状态分支 |
| E、D.10 | 有注册和隔离记录，但内部历史不全公开，且作者披露过一次训练侧接触评测记录 | 在我们的实验中先冻结协议、版本与数据，再发布可追溯日志；不把注册当作正确性认证 |
| E | 研究循环允许在重试后仍报错的任务离开比较 | 同时报出意向评测口径、完整任务口径和基础设施失败的敏感性分析 |
| F、C.1、经济审计 | 成本受 GPU 定价、利用率、缓存和调用基线影响；跨时间/并发的延迟含服务条件影响 | 在同一服务窗口配对，分报推理关键路径与墙钟时间，计入训练、校准和维护成本 |

第三方安全研究还需要额外的构念检查：环境中的“偏离标准计划”与“未经授权”不是同一个概念。一个不够快但合法的动作，可能不是标准下一步；一个能完成用户目标的动作，也可能同时泄露数据。不能直接用现成任务正确率充当安全标签。

## 8. 对成本与速度标题的核查

公开 Stage-2 汇总中，训练后组合的成本确实大幅下降，但该轮模型调用延迟更长。后续专用 GPU/批处理的较快结果属于另一种服务条件。两者可以同时成立，不构成矛盾，也不能将最便宜与最快的数字视为默认配置的联合表现。

按汇总中的每任务成本差与作者报告的训练、校准费用，算术回本约需 5,759 个任务。这个值不包含本项目未来的安全标注、适配、迁移再训练和运维费用，也不预测当前价格；只是对该历史设定的复算。

## 9. 对安全研究的直接启发

研究对象可以写成：在固定权限策略下，不可信工具内容是否改变委派、回退或复核决定，以及这种改变是否增加越权执行。

不要假设小模型一定更危险，也不要假设强模型能自动修复。一个高效控制器可能减少攻击暴露，也可能绕过本来有效的复核；方向应由实验决定。

建议先固定一个模拟业务环境，明确真实用户授权记录与外部文本的区别。攻击者只能修改指定工具返回中的非权威文本字段，不控制框架规则、模型参数、真实权限记录或工具实现。工具描述投毒属于额外权限，需要单独设置实验。

实验至少区分三层输出：控制判断是否改变、越权动作是否被提出、越权动作是否实际改变环境。若外部权限层挡住执行，要记录“尝试被拦截”，不能计作已执行，也不能因为无危害就认定模型判断正确。

为了识别共享控制额外带来的影响，使用相同攻击前状态做分支，比较原策略、强制交给 LLM、固定复核或规则策略。再在不改变攻击内容的条件下干预控制决定。共同前缀有助于归因，分支后状态分布变化仍需用完整轨迹报告。

测试攻击与阈值调优分开；同时报告干净合法任务完成率、攻击下合法任务完成率、越权执行率、覆盖率、复核率和总成本。首次实验的目标是确定机制是否存在，不是用小样本宣布普适安全保证。

## 10. 复用哪个实现

| 层次 | 优先入口 | 需要补什么 |
|---|---|---|
| 可控安全实验 | `research/src/jevharness/bench/env.py`、`harness/agent.py`、`harness/trajectory.py` | 权限状态、可控注入点、越权评判与记录；明确 oracle 仅供评测 |
| 真实消息流验证 | 根目录 `src/jevagentharness/` | 适配外部环境，验证消息角色、截断和工具调用是否完整 |
| 训练防御 | 先复用 SFT 数据流程 | 独立授权标签、未见攻击家族、相同标注预算；有必要再试 RL |

前轮对根目录代理的合成检查，只说明状态构造和动作预筛选的具体行为，不是本轮新发现，也不代表安全攻击成功。代理中的风险检查和 LLM 重写不能自动视为硬权限执行器。
