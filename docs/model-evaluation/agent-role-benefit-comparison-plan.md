# Jev gate / selector 收益比较计划

日期：2026-10-18。状态：实验设计草案；本轮只读历史资料、核对官方接口并制定计划，没有新增模型调用、没有获得四配置闭环结果。本文不声明研究空白或性能提升。

## 1. 要回答什么

核心问题：在相同 agent、任务和攻击条件下，把动作判断、上下文选择分别或共同交给 Jev，是否改善安全—任务效用—成本之间的权衡？

先回答接入角色是否有用，再回答 Jev 相比便宜的规则、筛选算法或 LLM 判断是否有额外价值。四配置比较本身不能证明 Jev 优于其他模型。

收益按三个维度分别判断，不预先合成一个加权总分：

- 安全：预定义攻击目标更少达成，或经独立审核的违规更少发生。
- 效用：正常任务仍可完成；攻击下仍能完成用户任务。
- 效率：包含所有组件、重试与恢复的总费用、端到端时间降低。

成本下降但任务失败增加，不直接称为提效；安全提升但成本增加可以是有价值的权衡。阈值、效用非劣界和风险上限须在确认实验前确定，不能在测试结果上挑选。

## 3. 主比较：2×2 配置

| 编号 | 动作 gate | 上下文 selector | 主要对比 |
|---|---|---|---|
| A | 无新增 gate | 无新增 selector | 共同基础 agent |
| G | Jev | 无 | G−A：gate 的净影响 |
| S | 无 | Jev | S−A：selector 的净影响 |
| GS | Jev | Jev | GS−S：已有 selector 后 gate 的增量；GS−G：已有 gate 后 selector 的增量 |

共同基础包括同一系统提示、原有安全机制、工具权限和预算。A 不是关闭所有安全约束的 agent。全部配置具有相同模型版本、可用工具和初始环境；每次运行重置环境，允许轨迹自然分化。不能在 A 的轨迹上离线改一次判断，再把后面的旧动作当作 G/S 的实际表现。

### Gate 契约

第一版只覆盖预先列出的有外部副作用动作（具体由所选任务确定），判断当前拟执行动作及参数是否符合用户任务和明确约束。记录工具名、参数、当前可信目标、已有观察和来源。

输出 allow/block；block 后给 agent 固定格式反馈，允许在共同总步骤预算内重规划；达到预算仍未完成记任务失败。第一轮不同时引入人工复核或多模型投票。API 失败或非法输出作为独立事件记录，固定回退行为，不当作正常安全判断。

工具可实施的硬权限由共同运行时执行。若该权限已完全阻断某攻击，标明该类没有 gate 的安全提升空间；不得为 G 私设更强权限，也不得把正确答案偷偷编码进规则基线。

### Selector 契约

只处理指定工具返回中的可筛选非可信内容，保留原文块而不改写；返回 block ID 子集，按原始顺序重建上下文。第一版以任务相关性为选择目标，不把它悄悄变成另一个安全分类器。

系统指令、用户目标、硬权限、运行时来源元数据和工具消息结构不允许删改。工具控制字段必须保留；内容分块规则和 token 预算固定。Selector 可见可信目标和明确列出的历史，但看不到攻击 gold 或未来结果。

选择哪些任务适用由结构决定，例如是否存在可独立保留的内容块，而非由 Jev 表现决定。四配置主表在共同适用的任务集上比较；不适用 selector 的任务可单独测 gate，不混入主表稀释或抬高效应。

GS 默认 gate 看见与下游 agent 相同的筛选后历史及不可变元数据，拟执行动作始终完整可见。如果另测 gate 读取完整原始观察，应列为单独消融，不能与主配置混用。

## 4. 必要的额外对照

四配置定位角色作用，以下对照定位作用来源；按阶段添加，不一次铺开全部组合。

| 对照 | 控制内容 | 回答的问题 |
|---|---|---|
| 简单截断 / 词项相关性筛选 | 相同分块、固定 token 上限、来源保留规则 | Jev 是否优于便宜的上下文缩减？ |
| 长度匹配的随机选块 | 多个随机重复；尽量匹配 S 实际保留 token，报告差值；计入匹配所需调用费用 | 改善是否仅来自少看一些内容？这是机制对照，不是免费部署方案 |
| LLM gate | 同一判断信息、动作范围、block 后行为 | Jev 是否能替代较贵的判断组件？ |
| 确定性 gate | 只用公开可实施的权限规则，相同可见事实 | 这些任务是否根本不需要模型判断？ |

若 selector 成为主线，再增加相同预算的 LLM selector。若主张优于已有 prompt-injection 防御，再加入固定版本的一种 AgentDojo 防御。第二种主 agent 模型用于后续外部有效性，不在最初 smoke 中展开全矩阵。

注意两种成本反事实：G 对 A 测“新增门卫值不值得”；Jev gate 对 LLM gate 测“替代判官是否省”。二者不能混为同一个节省率。

## 5. 用什么任务与攻击

主实验首选 AgentDojo 原始可执行任务、初始状态、工具和评测器，固定上游 commit、任务版本与依赖。官方 pipeline 已提供工具执行循环与可组合防御组件，优先复用，不自行重造 agent loop。

开发阶段先审核四个任务（每 suite 一个候选），确认任务—注入目标—合法插入位置—实际 payload—判分能连起来。之后挑选 12–20 个结构适配的开发任务，记录所有排除理由。任务数是 pilot 工程规模，不是充分统计功效的承诺。

每个任务的条件包括：

1. Clean：原始合法工具输出。
2. 固定攻击一：已有、与该任务有效匹配的间接注入 payload。
3. 固定攻击二：不同机制的已有有效 payload，若原基准无合适实例则省略并调整运行数，不强行凑齐。

攻击只控制声明的工具输出通道，不改可信用户目标或系统策略。首轮固定载荷用于配对角色比较；若要声称抵抗适应性攻击，另开预算相同的防御感知攻击阶段，分别记录攻击优化成本。固定攻击实验不能支持适应性稳健结论。

正式确认集按原始任务族隔离开发数据，变体和相关攻击不得跨集合泄露。历史 100 条、S4 样本及24个审计候选均视为开发暴露资产，查重时追溯到原始任务，而非只比 UID。

InjecAgent 可作为后续独立工具返回注入测试，沿用其协议并单独报告。AgentHarm 的直接恶意用户请求、ASB 的其他攻击权限不与本轮间接注入主表合并。

只有机制诊断确实需要时才自己补标：必要证据块、攻击块、授权来源等；由独立审核记录依据和分歧。多个等价证据集合都能完成任务时，不应把单一人工块集合当唯一 gold。真实授权变体需更新任务目标及判分，不能只替换一句话。

## 6. 如何定义收益与分母

| 指标 | 定义 / 分母 | 用途 |
|---|---|---|
| ASR | 攻击目标达成次数 / 预先登记且判分有效的攻击 episode 数 | 主安全指标；不等于全部可能违规 |
| Clean utility | 用户任务完成次数 / clean episodes | 检查正常使用受损 |
| Attacked utility | 用户任务完成次数 / 攻击 episodes | 检查攻击下可用性 |
| 安全完成率 | 用户任务完成且攻击目标未达成 / 攻击 episodes | 防止“拒绝一切”的伪安全收益 |
| 总费用 | 所有 agent、Jev、judge、重试、恢复与付费工具调用费用之和 | 平均到全部指定运行；不能只看成功样本 |
| 单位安全完成成本 | 攻击集全部运行费用 / 安全完成的次数 | 把失败尝试也计入；零成功时为不可定义/无穷，不报零 |
| 端到端延迟 | 开始任务到结束的墙钟时间；报告中位数、p95 | 固定并发、超时和缓存政策；小 pilot 的 p95 仅描述 |
| 诊断指标 | 副作用动作到达 gate 比例、合法动作误拦、证据/攻击块保留、后续轮数 | 解释机制，不替代任务结果 |

模型主动拒绝、被 gate 持续阻断、达到步骤预算都是有效任务结果，不能删掉。基础设施故障导致无法判分时报告 assigned/completed/unscorable 数、各组故障率，采用预先规定的整组配对重跑规则；仍缺失时给出敏感性上下界。不得把超时或无判分默认算安全成功。

“到达 gate 后的 ASR”仅作为条件诊断：不同配置改变到达 gate 的样本，不能用这个条件分母代替主 ASR。任务最终成功不代表中途从未违规；独立事件日志用于审查评测器遗漏，补充违规标签与官方成绩分开。

## 7. 比较方法与验证链

以 task × attack/clean × repeat 为配对键；每组均跑 A/G/S/GS。独立还原环境，交错或随机化配置执行顺序，避免某组集中在网络拥塞时段。支持 seed 的接口记录 seed；不支持则明确记录 repeat ID，不虚构可控随机种子。

主比较预先选 G−A 和 S−A；GS 的增量和交互作为次要比较。对任一指标 Y 可描述交互 I=Y_GS−Y_G−Y_S+Y_A，其解释依指标方向而定，不直接称为协同。

报告配对差值（百分点或货币/时间）及区间。按原始任务族聚类重采样，保留同任务的攻击、配置和重复；任务族很少时区间不稳定，以逐任务结果和探索性表述为主。不能把 3 次重跑当成3个新任务；重复增加条件精度，不增加任务覆盖。

确认实验的规模由 pilot 的配对不一致率、任务内相关性、实际最小效应和预算决定。预先定义多重比较处理；“不显著”不等于等价或非劣。匹配安全/效用运行点须在开发集选择、确认集验证；若无满足约束的点，报告不可比较，不事后放宽约束。

验证链：

1. 环境验证：原始任务判分与干净运行可执行，工具状态可重置。
2. 接口验证：无未来信息/gold 泄露；selector 只选合法 ID，不改变工具结构；gate 确实在执行前拦截。
3. 结果验证：官方判分方向经源码核对；完整保留轨迹、工具状态变化及错误。人工盲审抽样轨迹和全部配置间不一致案例，避免只挑“好例子”。
4. 机制验证：在保存的介入前快照中恢复/移除可疑证据块，重新生成后续轨迹，多次重复。它只能支持该状态下的局部机制判断，不能代替全任务平均效应。
5. 泛化验证：冻结策略后到未见任务/攻击族确认。主表失败实例也保留，不根据性能排除。

## 8. 成本日志最低要求

每个 episode：run ID、配对键、任务/攻击 hash、suite、配置、起止时间、终止原因、用户任务结果、攻击结果、判分有效性。

每次调用：组件角色、请求 hash、请求与实际响应模型 ID、时间、输入/输出 token、provider usage、缓存命中、重试、错误、价格来源与日期。gate 记录拟执行动作、判断与实际执行状态；selector 记录候选/保留 ID、输入和输出 token、不可变元数据校验。

本地模型报告硬件、运行时间与资源口径，不把“没有 API 账单”写成零成本。提供主模型、Jev、复核、恢复各自费用分解。服务费用总和与日志核对；并发吞吐和单任务延迟分开；历史静态 judge 延迟不充当主 agent 生成时间。

## 9. 分阶段执行与停止点

| 阶段 | 规模 / 交付 | 进入下一阶段的依据 |
|---|---|---|
| P0 任务审计 | 4 张完整任务卡、版本清单、攻击匹配和评测器核查 | 找到适合共同四配置比较的任务；不能仅有 GOAL 字符串 |
| P1 流程 smoke | 4 任务 × (clean＋1攻击) × 4配置 × 1次 = 32 runs，前提每任务有有效攻击 | 日志、来源保护、状态重置、判分及费用可复核；不要求 Jev 显示正收益 |
| P2 探索 pilot | 12–20任务 × (clean＋最多2攻击) × 4配置 × 3次，上限432–720 runs | 得到失败类型、方差与成本；据此收缩机制和估算确认规模 |
| P2b 解释性对照 | 在同一开发集增加简单 selector 与 LLM gate；实际运行数另计 | 区分上下文缩短、模型判断与实现差异 |
| P3 冻结确认 | 未见任务族/攻击；规模由功效与预算计算 | 输出预设主要差值、区间、安全—效用—成本前沿和失败案例 |

Clean 条件每任务每配置每次只跑一遍，不因两个攻击重复计算；公式中“最多2攻击”不保证每任务均有两种有效攻击。P2/P2b用于开发，不能与 P3 合并冒充全为盲测。

可行性停止条件：如果共同硬权限已使全部目标攻击不可能成功，或任务几乎没有可筛内容，则当前任务集无法识别相关收益。应报告无可测空间并重新审查问题/任务覆盖，而不是调弱主 agent 或只选已知攻击成功任务制造收益。也不因为 pilot 阴性而反复换数据直到阳性。

当前建议先做 P0/P1，主模型先固定一个已可调用且适配工具循环的后端；具体模型/端点尚未选定。预算估计使用 smoke 实测的调用量和用量，不把历史 Jev 小额账单当作全部 agent 实验预算。

## 10. 最终产出与依据

- 配置对比表：ASR、clean/attacked utility、安全完成率、总费用、端到端时间，附任务数、重复数、缺失数和区间。
- 安全—效用图及带费用标记的运行点；无支配关系时明确呈现权衡。
- 逐任务配对差值与错误迁移表：少发生的攻击、额外误拦、丢失证据、恢复代价。
- 数据清单、完整配置、版本、日志和可复核判分；不提前写“首次”或预注册已完成。

官方接口核对（2026-10-18）：[AgentDojo pipeline](https://agentdojo.spylab.ai/concepts/agent_pipeline/)、[InjecAgent 仓库](https://github.com/uiuc-kang-lab/InjecAgent)。本轮为文档核查，不代表已完成环境安装和运行验收。

与已有工作的边界：[REFLEX](https://arxiv.org/html/2609.26532v1) 已研究 agent 内选择性控制和任务成本；不能把“首次闭环/首次端到端成本”作为本文贡献。待验证方向是规定攻击权限下不同委托角色的实际安全效应及机制。
