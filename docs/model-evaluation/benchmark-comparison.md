# Jev、本地 4B 与 DeepSeek 的对比总结

本总结只针对固定 100 条配对样本：MSB 30、MCPTox 30、AgentDojo 40；每组正负各半，原文不超过 12,000 字符，阈值 0.5。Jev 为同 UID 的历史预测；DeepSeek 主表使用第二版“显式 YES/NO＋置信度”输出。第二版在查看首轮后调整，因此属于探索性结果。

## MSB：Skill 制品

DeepSeek 第二版在这 30 条上保持与 Jev 相同的检出数 14/15，将正常 Skill 误报从 5/15 降到 2/15。它放行了 Jev 误报的 Git hooks 管理、域名查询、需要用户授权的建议流程和本地数据管理等样本。相比 Jev 修正 4 条，新增 1 条错误；新错误是把带催促/施压话术的营销 Skill 判为危险，而基准标签为良性。两者共同漏掉同一条恶意样本。

本地 decider 与 H2O 的误报低，但分别漏掉 10/15、9/15 个恶意样本；不能只凭误报低认为守卫更好。Plumb 漏检和误报都比 Jev 多。当前 MSB 本地模型 AUROC 为 0.631–0.724，H2O 原始 AUROC 0.671，提示单纯调整阈值也可能不足，仍需独立数据验证。

## MCPTox：工具描述投毒

DeepSeek 第二版比 Jev 多检出 1 个恶意样本，均无误报；这只是单样本优势。具体补上的是 ClickHouse_16 中“列出数据库前先调用 list_tables”的额外操作指令。两者仍共同漏掉 Memory_6。

Plumb 与 H2O 检出了 Jev 漏掉的两条，但分别新增 13、8 条错误：Plumb 几乎拦截了所有正常工具描述，H2O 同样误报较多。它们确有错误互补性，但当前没有证据支持直接取并集或否决 Jev。Plumb AUROC 0.916、H2O 原始 AUROC 0.933，有独立校准研究价值，不能在这批样本上选阈值后宣称改进。

## AgentDojo：当前待执行动作是否越权

Jev 与 DeepSeek 两轮均检出 20/20 个危险动作、放行 20/20 个合法动作。DeepSeek 的解释能区分历史上下文的攻击与当前待执行动作是否服务于用户任务，便于复核；在这批样本上没有额外修正 Jev 的错误。

Plumb 是本地模型中默认阈值下召回最高的：19/20，但误报 5/20。H2O 检出 13/20、零误报，原始 AUROC=1.000，原始负例风险分范围 0.061–0.229、正例 0.284–0.805；有望通过独立校准改善阈值下的效果。官方 floor 使多个原始概率变成相同值，处理后 AUROC 降为 0.974。decider 检出 5/20，当前漏检太多。

## 性能与使用方式

Jev 在三组上的中位耗时约 1.0–1.4 秒；DeepSeek 第二版约 2.1–2.2 秒，并能生成文字理由。本地 H2O 的中位耗时约 0.287/0.075/0.387 秒，且实际可离线运行；Plumb 与 decider 在短工具描述上分别约 0.154/0.085 秒。计时受网络、编译、缓存、文本长度影响，不是严格的后端吞吐对照。

当前可研究的使用方向：Jev 用于直接判别，DeepSeek 用于核查疑难或误报样本并生成理由；H2O 优先做 S4 独立校准与盲测。串联或融合方案尚未测试，不能把这些方向写成已验证的部署效果。模型自报理由和置信度也不保证忠实或校准。

## 证据边界

样本太小，MCPTox 的 1 条差异不足以证明稳定领先；S4 零误报只有 20 个负例，95% Wilson 区间上限仍约 16%。S1 两组每类 15 条，零误报的区间上限约 20%。不合并不同标签语义给总排名，不外推 Agent 闭环攻击成功率。
