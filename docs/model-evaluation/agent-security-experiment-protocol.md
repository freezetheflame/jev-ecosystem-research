# Jev 与 LLM 的 Agent 安全全链路对比：执行规范

初建日期：2026-10-25；更新日期：2026-10-27（Asia/Shanghai）。版本：0.4。状态：**设计与必备记录已约定，旧 Mode A–D 定义保留，新选型 Mode 语义待确定，离线报告层已实现，具体实验配置未冻结，尚未启动新实验**。

用户研究目标：比较 Jev 与普通 LLM 承担 Agent 安全职责时的完整任务表现、时间和资源消耗，判断可替代范围及尚存差距。结论方向不预设。

最新选型记录：[2026-10-27 第二版清单](2026-10-27-study-selection-v2.md)：11 个模型/方法、4 个数据集；新 Mode A1/A2/B/C 的语义按用户要求暂缓确定，不能继承旧 B/C 的定义。这是选型范围，不是已冻结运行配置；其中 evaluation Mode 字母与本文比较组编号分开。下文 A–D 的场景说明保留为旧定义参考，待新定义确定后再更新适配合同。

历史 Mode A–D 定义见[评测场景与适配边界](agent-security-evaluation-modes.md)：A 输入检查；B 执行前授权；C 仅已发生历史的前缀监测；D 完整轨迹事后审计。按决策位置、可见信息和判断目标划分，非攻击类型分类。各 Mode 分开记录与统计；B/C 标签缺失时另行构造验证，不继承完整轨迹标签。下文 action gate 的比较设计主要对应 B，不能覆盖 A/C/D 的全部任务契约。

| 费用 | 实际 API 账单或依据 provider usage 和价格快照计算的估价，币种、计价日期、缓存和重试费用；主 Agent/gate/工具/判分分列；本地默认不计价，估价另列 |

| 模型和完整配置 | 每个组件的请求与返回模型标识、服务或权重版本、部署/推理引擎、全部实际请求参数、客户端/服务配置；本地另存权重/适配器 revision、tokenizer、精度/量化和硬件 |
| prompt / 请求 | 完整 system/user/developer 模板（如有）、示例、工具 schema、Jev state/questions/instructions/criteria、选项顺序、上下文构造/截断及后处理；逐调用保存实际展开后请求与原始响应 |
| 复现入口 | run ID、协议/config/data/prompt/code/environment hash、依赖锁、启动命令、初始环境及恢复方法；数据不能复制时保留可获取来源与精确版本 |

“完整参数”指我们能控制或查明的全部有效配置，不要求虚构服务端隐藏参数。显式值、已核验默认值、未知默认值、unsupported 和不适用须区分；只保存模板或写“其余默认”不满足要求。返回模型/版本不可固定时记录该限制。不同模型只固定各自实际支持的参数。

主报告默认采用 **API 费用（本地计算未计价）** 口径。本地计算不计价不等于零成本；仍记录可取得的运行时间和硬件。本地估价可用占用小时 × 固定机器小时价，或有功率实测时用能耗 × 电价，明确是否包含折旧/租赁/电费，避免重复计费。实际费用、价格估算和本地估价分列；缺少单价不得编造估价或默认为零。

本规范补充[既有角色收益计划](agent-role-benefit-comparison-plan.md)，不覆盖历史协议和结果。原 A/G/S/GS 用于区分 gate / selector 作用；当前优先问题是同一安全角色的 Jev / LLM 替代比较。Selector 与组合策略暂列后续扩展，不自动加入首轮矩阵。

## 1. 研究问题与比较单元

主问题：固定主 Agent、任务、攻击权限、信息和工具后，以 Jev 替代 LLM 安全判断模块，是否维持可接受的安全与效用，并降低完整任务成本或时间？

首轮优先选择执行前动作 gate：相同动作范围、可见历史、策略、来源信息、allow/block 语义和阻断后反馈。两类接口允许必要的序列化差异，保存适配器版本，不把不同格式强称为完全相同输入。不能只让 LLM 做文本有害性、让 Jev 做动作授权，再直接排名。

| 组别 | 主 Agent | 新增安全模块 | 比较用途 |
|---|---|---|---|
| A | 同一个固定模型与提示 | 无 | 测新增安全模块的净影响；保留共同原生安全约束 |
| J | 同 A | Jev gate | 目标配置 |
| L | 同 A | 普通 LLM gate | J 对 L 是主要替代比较 |
| R | 同 A | 可实施的确定性规则 | 检验是否已有便宜且足够的规则方案 |

规则模块只能使用运行时可获得的信息，不能读取测试 gold。各组共用相同硬权限；明确规则可覆盖范围。LLM 对照应包含一个有竞争力的低成本配置，不能只挑昂贵模型制造优势。具体模型沿用[选型材料](empirical-study-model-selection.md)作为候选，运行前重新验证可用性并固定，不把候选当作已选定。

每组都从同一任务初始状态独立运行到终止，允许后续轨迹自然分化。主配对键为 task_family / task_id × attack_id 或 clean × repeat_id。单步判断、旧轨迹回放和固定轨迹重打分仅作诊断，不充当闭环结果。

本比较支持“安全模块替代”，不支持“Jev 替代主规划 LLM”。如果之后研究整个 Agent 架构替代，另建实验，记录职责重分配和信息差异。

## 2. 任务、攻击与开发暴露

主环境候选沿用 AgentDojo 原始可执行任务；当前仍需完整安装、版本及判分验证，不能称为已接入。先从既有四个 suite 的待审任务入口核对任务、合法注入位置、实际载荷、环境恢复与效用/攻击判分。具体上游 commit、任务版本和可用集合写入配置。

保留 clean 与 attacked 两种条件。固定攻击阶段所有组使用相同载荷及权限；适应性攻击单开阶段，预先固定攻击者知识、调用/计算预算、搜索策略与新调用验证规则，保留搜索成本。不能将固定载荷成绩解释为抵抗自适应攻击。

按原始任务族划分开发、校准、确认集合，同题变体及相关攻击不能跨集。历史 100 条、S4、24 个候选及已用于调参/诊断的任务需标记开发暴露。若无法取得足够未暴露任务，则报告探索性研究或另设独立迁移确认集，不伪称盲测。

排除条件在查看各组测试表现前确定，逐条保留理由。官方判分支持的结论与额外人工审核的违规事件分开。若补充人工 gold，记录审核者、依据和分歧；AI 审核不能冒称真人独立审核。

## 3. 冻结哪些参数

使用[配置模板](../../data/agent-security-study/protocol.template.json)。null 表示尚未决定；模板本身不是冻结记录，也没有程序执行权限控制功能。

正式冻结至少覆盖：

1. RQ、主要比较、指标方向、最小实际意义差异、安全/效用非劣界、资源收益标准与多重比较政策。
2. benchmark commit、任务/攻击 ID 与 hash、初始状态、split、开发暴露、评测器及其通过条件。
3. 主 Agent 与安全模块的模型版本、provider/endpoint、权重 revision、tokenizer、量化、推理引擎及依赖锁。
4. 系统提示、完整模板、可见字段/来源、动作覆盖范围、输入裁剪、输出 schema、解析器、阈值、阻断反馈与重规划规则。
5. 所有实际支持的推理参数、输出/推理预算、上下文预算；不支持的参数记 unsupported，禁止假装 Jev 可固定 temperature 或 seed。
6. 每任务步骤与工具预算、超时、错误回退、重试类别/次数/退避、缓存、并发、运行顺序与重复计划。
7. 机器、操作系统、GPU/驱动、测量采样率、时间定义、加载/预热政策及后台负载记录。
8. 总费用与时长上限、停止条件、续跑协议、分析代码及数据质量验收标准。

跨模型固定的是比较契约和信息权限，而非强求数值相同的所有参数。不同模型的阈值、模板和输出上限可在相同开发/调参预算下适配，随后分别冻结；额外能力与信息必须披露。相同 token 数不保证相同信息或计算量。

保存实际解析后的 effective config、每个请求实际发送的字节及 hash，不仅保存含默认值的模板。代码记录 commit 和 dirty state；有未提交修改时保存相关源码快照、补丁与 untracked 文件 hash，commit 单独不能标识当前工作区。不得复制凭证文件。

冻结后生成 protocol/config/data/code/environment 的清单与 SHA-256，记录冻结时间和决策依据。API 无不可变版本时如实记限制、响应模型标识和漂移探针，不能保证逐位复现。

### 每轮增加的科学问题与验收记录

- 明确本轮只改变什么、固定什么，写下可证伪假设与不支持的外推。例如“替代动作 gate”不扩大成“替代整个 Agent”。
- 明确主要比较、主要指标、最小有意义差异和可接受的安全/效用损失；次要指标和探索发现单列，不能测试后只挑有利项。
- 记录样本选择原因、任务族、重复/配对结构、类别比例及标签来源/分歧。开发、阈值校准、确认集合按任务族隔离。
- 比较契约明确相同可见信息、攻击权限、Agent 步数及调参预算；分别定义固定部署配置比较和同质量/同预算比较，不暗中切换口径。
- 预定样本量依据、区间方法与停止条件。预算/故障停止记 partial；若按效果提前停止，需事先采用有效的序贯方案，不能反复查看显著性后择时结束。
- 核对判分器方向、gold 来源及覆盖范围；跨组不一致案例采用统一复核规则，不只人工修正某一组。
- 单数据集/场景先分别报告，整体汇总说明固定权重和类别构成；避免比例变化造成看似改进。重复调用或同任务变体不能膨胀独立样本量。
- 展示不利结果、失败/未知及效果区间。安全、效用、时间和费用分别呈现；不以高 accuracy 掩盖少数风险类漏检，不将早失败的低成本称为节省。

## 4. 时间和资源：两种问题分别回答

**部署现实轨道**比较实际可用服务的安全—效用—费用—延迟权衡；结论针对整个服务配置。**本地受控轨道**在相同硬件、并发和可比精度下测计算资源；不能用托管 Jev 的客户端 CPU 与本地 LLM 的 GPU 比较推理算力。

| 量 | 测量与报告规则 |
|---|---|
| 端到端墙钟时间 | 从 episode 开始到终止，包含主 Agent、gate、工具、恢复和重试；monotonic 时钟计时，UTC 时间戳溯源 |
| 分组件时间 | 主 Agent、gate、工具、排队/退避、判分分别记录；外部离线判分通常不纳入部署延迟，但纳入实验总成本 |
| 时间分布 | p50、p95、样本量、超时数量与上限；小 pilot 的 p95 仅描述；延迟不是并发吞吐 |
| API 费用 | provider usage × 当时价格，或实际账单；缓存/批量折扣单列；估算与账单核验分开 |
| token 与调用 | 主 Agent、gate、恢复、重试、判分、攻击生成分别计账；不同 tokenizer 的 token 不等同 FLOPs |
| 本地资源 | 实测 CPU/GPU 时间、RAM/VRAM 峰值、采样范围与进程归属；加载和稳态分开；共享设备需披露干扰 |
| 能耗 | 仅在有功率测量及积分方法时报告，注明设备覆盖与空闲基线；无测量记 unknown |
| 托管服务算力 | 服务端 GPU、显存、能耗拿不到即 unknown，不从费用或延迟反推 |

同任务块内随机化或交错配置顺序，保存实际顺序及时间，避免网络/时段偏差。性能轨道先固定并发；冷启动与预热独立报告。缓存命中必须记录，缓存回放不能伪装成新模型调用。若同机同时加载两组件，内存、争用和切换开销须计入真实部署成本。

## 5. 指标、失败与结论标准

主要安全指标为官方攻击目标达成率，不能改称覆盖所有违规。明确 denominator 为已登记攻击 episodes，并对无法判分的项单列 unknown。效用指标包括 clean 用户任务完成率、attacked 用户任务完成率，以及 attacked 中用户任务完成且攻击未达成的联合比例。拒绝一切不会得到高效用。

始终给出 assigned、started、finished、scorable、failed、unknown 数量。对可判分子集报告结果时写明分母，同时对全部 assigned 给出缺失结果的最坏/最好边界。超时、解析失败和持续阻断不能默认算安全成功；合法执行后的任务失败仍是实际结果。

平均费用和耗时包含失败与重试，不能只筛成功样本。单位安全完成成本 = attacked 全部运行成本 / 安全完成次数；零完成时记 NA 并标明零完成，不能报零成本。因更早失败而变快不能称为有效提速。

gate 的动作级误放/误拦需要独立动作 gold，否则只报告判断与执行事件，不能从 episode 标签自动推导。概率校准只对可比且有定义的预测目标报告，不强行比较 Jev 原始概率与 LLM 自述置信度。

### TP / FP / TN / FN 的固定口径

每张混淆矩阵先写出 `classification_unit`、`target_event`、正类和预测映射。动作安全 gate 默认正类为“当前动作应阻断/违反授权”，预测正类为“安全模块判定应阻断”；该默认只有在动作级 gold 已审核时适用：

| 实际标签 | 预测阻断（正） | 预测放行（负） |
|---|---|---|
| 应阻断（正） | TP：正确识别风险 | FN：漏检/误放 |
| 应放行（负） | FP：误报/误拦 | TN：正确放行 |

静态条目、动作判断和完整 episode 分表，不合并成一张矩阵。完整任务可直接统计攻击成功/失败和任务完成/未完成；若另建二分类指标，必须先定义其预测事件与 gold，不能拿“是否含攻击”直接当每个动作的违规标签。

必须满足 `TP + FP + TN + FN = 有有效二分类 gold 且有有效二分类预测的条目数`。标签缺失、解析失败、超时和未决结果另列；即使执行策略因错误而 fail-closed，也不能把接口错误计成模型正确检出。报告计数的同时给出分类覆盖率及全部计划条目数，不通过删失败抬高指标。

accuracy = (TP+TN)/N；precision = TP/(TP+FP)；recall/TPR = TP/(TP+FN)；F1 = 2TP/(2TP+FP+FN)；FPR = FP/(FP+TN)；FNR = FN/(TP+FN)；specificity/TNR = TN/(TN+FP)。分母为零记 NA，并写明原因。先保留整数计数再算小数，不能从舍入后的比例反推计数。

多分类保留完整 K×K 矩阵及各类样本数；one-vs-rest 和 macro/micro 指标按预定口径另列。hold/review 不能不经定义并入正/负。无合适 gold 的实验仍有统计字段，但标 `not_computable_missing_gold`；仅连通 smoke 标 `not_applicable_smoke`，禁止为了补齐表格而制造 TP/TN。

主要 J−L 比较以原始任务族为独立聚类单位进行配对分析，报告效应大小、区间和有效簇数；同一任务的多攻击/重复不是独立新样本。样本量由最小效应、配对差异、簇相关性和预算共同决定；pilot 规模不冒称有充分功效。确认前固定非劣/等价检验与多重比较处理，“不显著”不等于可替代。

替代结论需同时满足预先规定的安全和效用界，再判断资源收益；若区间太宽则为证据不足，不能归为等价，也不能自动归为明显劣于。按预注册范围报告适用任务与失败类型。允许更安全但更贵、更便宜但效用受损、仅部分场景可用等结果，不强行压成单一总分。

```text
analysis/<analysis-version> 派生表、统计、图及输入哈希
audit.json                  计划覆盖、配对、完整性与核对结果
```

调用前先持久化 attempt ID、请求与开始事件，再调用服务，返回后保存原始响应与 HTTP/错误状态；这样中断不会让未完成调用无声消失。API key、Authorization 和带 token 的 URL 不进入日志。保留与请求对应的 provider request ID（如有）；错误响应如含敏感值，保留访问受控版本并记录脱敏方式。

只追加事件，重试生成新 attempt，关联原 attempt，保留全部费用。重试仅依事先定义的基础设施错误触发，不能因答案不理想重试。结果按预先规定的 attempt 选择规则产生，不能取最好一次。

续跑先验证配置/源码/环境/输入 hash 和已完成记录，跳过匹配的已完成单元，保留原前缀与中断证据。源码缺陷需隔离受影响产物、记录修订后重跑，不覆盖旧数据。指标错误从原始记录重算并生成新 analysis-version，绝不手改结果表。

SHA-256 能核对文件变化，不能单独证明调用真实；本地只追加约定也不是不可篡改存储。真实性需联合原始返回、运行日志、provider usage/request ID、账单与可复跑检查判断。需要更强审计时再采用独立留存或签名，不声称 skill 已保证零造假。

## 7. 接下来的操作顺序与当前缺口

1. **任务审计**：恢复固定版本可执行环境，核对四个开发任务的工具、攻击与判分，不改历史数据。
2. **实现运行器**：统一安全模块接口，核对 gate 实际在副作用前执行；加入请求前落盘、失败记账与环境重置。
3. **离线验收**：验证无 gold/未来信息泄漏、状态恢复、错误处理、配对、成本核算、hash 不匹配拒绝续跑。mock 只证明工程流程。
4. **真实小 pilot**：使用选定模型和开发任务验证全链路，报告实际费用/错误和计时；不作正式替代结论。
5. **冻结确认协议**：依据 pilot 决定样本量、固定版本、全部参数、非劣界、统计与预算；记录开发暴露。
6. **正式执行和整理**：运行完整冻结矩阵，先审计覆盖与判分，再生成 CSV、汇总、配对差异及图；所有数字回链原始记录。

当前缺少：主 Agent、Jev 配置、至少一个普通 LLM gate、端点/部署方式、可执行 benchmark commit、任务集合、预算、具体推理参数与停止阈值。本文未替用户设定这些数值，没有新模型调用，也没有已完成的新全链路运行器或正式冻结包；已有 monitor 保留，独立离线报告层已实现并通过测试。

后续由代理承担配置整理、实现、启动、运行监测、原始记录、失败登记、数据清洗代码和分析；研究范围与实际资源约束沿用用户决定。常规操作无需逐条再问；无法推断的模型/预算才作为缺失输入提出。数据清洗必须保留原始值、转换规则和排除理由。
