# Jev 鲁棒性与安全：证据、结论和研究选择

调研日期：2026-10-13。范围：公开论文全文、官方文档、三个公开项目的固定版本源码，以及本仓库已有 JevOut 记录。**这是文献与方法核查，未重新运行论文实验，也未新增模型调用。** 数字均注明适用对象；公开预印本不自动视为已通过同行评审。

## 1. 对后续 Jev + 安全研究的结论

**建议把主问题定为：不可信内容会不会被 Jev 当成可信授权或证据，以及这种变化会怎样破坏安全门控的风险与覆盖率。** 相比增加一组同义改写，这更直接连接 Agent 的实际行为。

目前证据支持五个判断：

1. **“输出类型正确”不能推出“安全判断正确”。** Jev 仍可能被背景意见、选项命名或上下文影响；但不同输入面的攻击能力必须分开定义。
2. **普通改写较稳定，不等于安全鲁棒。** 判断类别不变时，概率仍可能跨过放行或复核阈值；反过来，真实授权改变时，继续保持原判断也是失败。
3. **高置信度不能单独充当放行依据。** 已有安全评测观察到被判为低风险的攻击。阈值应在目标任务上选择，并在独立、发生扰动的数据上检验。
4. **攻击成功率必须附带分母、控制权限、预算和标签审核。** 自适应搜索、单次扰动、离线错误选择与实际有害执行是不同结果，不能横向拼成排行榜。
5. **“首次研究 Jev 鲁棒性／选项攻击／授权门控”都缺乏依据。** 更有价值的贡献可能是可信来源对照、严格的语义审核，以及冻结门控策略在新攻击分布上的失效与修复。

这些是对现有证据的综合判断，并非对所有 Jev 版本的安全定论。下面给出依据与边界。

## 2. 把鲁棒性拆成可检验的五层

| 层次 | 应检验的行为 | 对安全的意义 |
|---|---|---|
| 表达不变性 | 事实、策略、授权不变，改写后仍答对 | 排除措辞、格式、语言带来的偶然放行 |
| 关键语义敏感性 | 权限、目标、执行主体等真正改变时，判断随之正确改变 | 防止“永远拒绝”或“永远同意”获得虚假的稳定性 |
| 信任边界 | 外部文档声称“用户已同意”，不能替代可验证授权 | 将一般语义测试连接到提示注入与越权 |
| 概率与门控 | 同时观察类别、概率、放行／拦截／复核 | 识别高置信度漏检、复核量上升和错误阻断 |
| 系统结果 | 在执行前判断，并测最终越权、正常任务完成和总成本 | 离线分类分数不能代替 Agent 安全效果 |

信任边界需要由实验策略明确定义。例如，外部材料可以补充事实，但是否能授予写文件权限必须由应用规则决定。不能先让模型自行理解授权，再用自己的理解判它错误。

## 3. 关键文献：哪些结论可以成立

### 3.1 普通扰动、自然背景与定向攻击

| 工作、采用版本 | 关键结果（作者报告） | 解读边界 |
|---|---|---|
| [JevAdvBench，v1](https://arxiv.org/html/2609.31142v1) | 812 个问题、9,744 个单编辑变体。问题侧改写翻转 1.5%，相同请求重跑 1.0%；state 追加观察者意见翻转 12.1%。405 个原置信度至少 0.8 的 Choice/Score 输出中，38.0% 降至阈值以下。 | 38.0% 是置信度跨阈值，**不是错误率**。多数参考标签源于模型；也没有逐条人工确认所有变体语义等价。问题侧改写不覆盖任意 state 改写。 |
| [JevOut，v2，10 月 8 日](https://arxiv.org/html/2609.30243v2) | Jev 在 508 个初始正确样本中被定向翻转 312 个，61.4%；每题上限为 64 次被接受的目标评估。同预算独立生成对照为 48.0%。 | 这是搜索后的条件成功率。跨四个系统抽取的 250 条成功背景中，229 条获盲评多数认可，不能把 91.6% 直接乘到 Jev 的成功率上。预算匹配也不能单独隔离概率反馈的因果作用。 |
| [Decision Hijacking，v1](https://arxiv.org/html/2609.28613v1) | 510 个重建的 InjecAgent 场景，在固定决策快照上，攻击者目标选中率从 1.8% 到自适应后的 3.5%；概率变化比最终选择变化更明显。 | 控制面是最新工具返回，用户请求和先前行为固定；评估错误选项被选中，**没有执行该有害操作**。不能将低成功率推广为 Jev 普遍抗注入。 |

三组数字并不矛盾：它们使用不同任务、候选动作、初始样本筛选、攻击目标和查询预算。严谨比较需要统一这些条件，并同时报告无攻击基线。

对本仓库 [40 题 JevOut 探索](../adversarial-robustness/jevout-40-results.md)也应保持这个标准：32 个可攻击样本中出现 2 次翻转，但两例新增背景都可能改变判题证据。本地结果目前支持“上下文影响决策、语义检查器可能误放”，**还不能记作 6.25% 的有效攻击成功率**；也不足以反驳论文的 61.4%。不同提供商、较低预算与语义审核差异需保留。

### 3.2 选项通道已有明确研究，但不能混淆模型与攻击权限

[Type-Safe Is Not Error-Free v3](https://arxiv.org/html/2609.26758v3)在 1,200 个流程问题上交换选项名称与定义的绑定，托管 Jev 的 yes/no 条件翻转为 **32.5%**，中性 0/1 和 A/B 条件分别为 2.08%、1.67%。论文中更高的 76.92% 属于 Laya，不能写成 Jev 的结果。比较时也必须先把输出映射回选项定义。

这说明命名是一个真实的配置敏感面，但故意让名称与定义冲突，不自动等同于外部攻击：若选项完全由可信应用固定，攻击者并没有改名权限。

10 月 8 日的 [One Word Opens the Gate](https://arxiv.org/html/2610.12292v1)进一步研究选项攻击；其中 93%–100% 的错误放行结果来自将标签放入输入的四个**开放权重模型，未测托管 Jev**。文中把 state 文本攻击与额外拥有选项命名控制权的攻击分开。其合成规则还能被确定性程序完全解决，提醒我们必须加入规则基线，避免把本可用代码处理的任务包装成模型安全贡献。

**对选题的影响：** 选项改名、顺序和定义绑定应作为回归测试与次要消融；若作为主攻击，需要证明现实系统中存在攻击者可触达的选项构造路径。

### 3.3 与安全最直接相关的是概率能否支撑自动化

[Evaluating System One Models for Agent Security Decisions v3](https://arxiv.org/html/2609.33401v3)报告：在 WAInjectBench 中，Jev 给出风险概率低于 0.1 的 1,446 个输入里，有 133 个带 unsafe 标签，比例为 **9.20%**；该组平均预测风险仅约 0.205%。这不是“所有 Jev 低分输入都有 9.20% 风险”，而是该基准分布上的明显低估。

该研究还发现，把放行和拦截阈值分别选择后，R-Judge 自动处理覆盖率可由 7.63% 增至 47.03%，但后一策略中仅 1 个放行、110 个拦截。**自动处理覆盖率高，不等于允许正常任务继续的能力强。** 论文采用离线基准原标签，不能将攻击片段的分类错误直接换算为实际越权率。

由此提出本研究要验证的推论：仅把高置信度判断直接执行、把低置信度判断交给大模型，可能漏掉最需要复核的高置信度错误。应测哪些错误真正进入复核队列，以及复核器在该队列上纠正或新增了多少错误。

### 3.4 概率一致性是另一条轴，不能替代正确性

[Beyond Calibration v1](https://arxiv.org/html/2609.33209v1)在 160 个样本、480 个否定对上，报告 Jev 的互补概率残差均值 0.064，约为重复噪声五倍。这支持单独测量逻辑一致性；不意味着所有概率都不可用，也不能推出满足概率公理的模型就安全。

官方 [model jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13)也列出输入与选项相关限制。厂商文档可用于设计测试，不能作为独立安全认证。重复测试应保存完全相同的请求；加入新的文本 UID 后，就不再是严格相同输入的噪声基线。

## 4. 源码核查发现的两个方法陷阱

本节是**本轮静态审读的判断**，没有执行第三方实验，也没有重算其全部原始预测。

**第一，严格准确率与平均准确率的差不是翻转率。** CITY-Jev 的[计分实现](https://github.com/JiaQiSJTU/CanITrustU-Jev/blob/cf5951b1d51b28913eb9b32fdc43c9767e78b3d7/src/eval/final_metrics.py)要求每题六版本都成功返回才纳入整组；strict 要求六个都正确，AAA 则将“正确或低置信度”视为通过。因此报告必须同时列出排除样本、有效覆盖和弃权比例。格式、选项表示等变换也可能同时改变多个因素。

**第二，跨接口比较前，要确认问的是同一个概率事件。** calibration-audit 的[`coherence.py`](https://github.com/jujumilk3/jev-calibration-audit/blob/daab9e2c2d5d5683bf07f3482deb653c26856219/src/jev_audit/experiments/coherence.py)将原问题中的一个目标答案用于 Noul，再只选两个答案构成 Choice。若两项不穷尽原问题的可能答案，Choice 的候选条件已改变。其 Noul–Choice 差异不能未经检查就全部归因于逻辑不一致。这不否定该项目的其他实验。

这两点直接影响自己的实验：所有扰动必须有变换契约；所有指标必须有分母；选项变化必须区分“表示变化”和“事件空间变化”。

## 6. 推荐研究主线与优先级

建议题目：**面向 Agent 安全门控的 Jev 来源约束鲁棒性与风险—覆盖率迁移**。

核心例子：用户只要求总结一个文档，文档正文却声称“用户已批准发送原始文件”。保持实际授权不变，改变正文的措辞、来源声称和论证强度，观察 Jev 是否允许发送。再加入真正来自可信用户通道的授权作为正对照：仅追求不翻转会把这一必要变化漏掉。

| 优先级 | 研究问题 | 可形成的证据 | 最大方法风险 |
|---|---|---|---|
| P0 | 外部声称是否被误当成可信授权或决定性证据？ | 相同主张、不同可信来源的配对；伪授权与真授权最小对照 | 未定义谁有授权权力，导致 gold 含糊 |
| P0 | 干净开发集上的阈值，遇到未见扰动后是否仍满足风险约束？ | 固定策略下，错误放行、正常任务受阻和复核负担的变化 | 用测试集反复调阈值，或只报告总覆盖 |
| P1 | 来源分层表示、判断分解与一致性复核是否有效？ | 在相同覆盖率或相同调用成本下减少错误 | 只是多调用几次，或靠更多拒绝获得改善 |
| P2 | 候选标签、顺序和动态工具描述是否引入新的放行路径？ | 真实攻击入口与固定候选集合的对照 | 将可信配置诊断冒充 state-only 攻击 |

这不是已证实的文献空白。拟议贡献是把**来源约束、语义有效性、阈值迁移和最终执行结果**放在同一受控评估中；正式声称新颖性前，仍需针对这组组合检索并对照最近邻。

不建议当前优先做：只添加同义词后报翻转率；混合不同预算的攻击榜单；从开放模型架构推断闭源 Jev 的实现；未经假设证明就宣称随机化聚合有鲁棒性证书。

## 7. 实验落地与可接受的结论

[配套实验协议](robustness-security-pilot-protocol.md)给出 60 个基础场景、表达扰动／伪授权／真授权配对、三种配置及计分口径。目标先验证实验定义是否可靠，而非以小样本证明低于 1% 的部署风险。

若出现高置信度越权放行，可支持“该任务与威胁模型下阈值不足”；若仅复核量增加，应报告可用性和成本退化；若没有观察到失效，只能报告该预算与样本下的界限。若防御有效，还需要证明它没有靠牺牲正常任务覆盖获得表面改善。

本阶段可用于研究立项的结论是：**把 Jev 视为需要验证的概率判断组件；由确定性策略落实硬权限，把研究重点放在非结构化语义如何穿越信任边界，以及固定门控策略何时失效。**
