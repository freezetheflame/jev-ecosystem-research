### 2.1 三篇只在 bib 里、但直接压在你 RQ3/RQ4 上的工作 [W]

- **2606.22659 "Confidently Wrong"**：PI 检测器只在干净集上定一个阈值，然后**冻结并搬运到五种分布迁移**；报告 severity = 漏检攻击上的置信度：**所有迁移、所有检测器都在 0.99–1.00，而 FNR 在 0.01–0.97 之间**——"漏的时候几乎总是很自信"；pooled 校准误差完全测不出来。这就是你 RQ3 的测量设计模板（且证明该现象真实存在），你必须引用并把 delta 定在"执行级 + 策略设计 + Jev 的 typed 输出"上。
- **REFLEX 2609.26532**：Jev 做快速 typed 决策层、低置信回落到强 LLM，100 任务上 95% 成功率、强模型调用降 72.7%；并指出可靠性取决于**候选集大小**与**授权边界附近的近似合法选项**。这几乎是你 RQ3 的"怎么用 Jev 的判断"和 RQ4 的"降成本"的已发表版本。
- **2609.29769**：Jev/Decider 对三种 flash 判官，七个基准九组 panel；"便宜 16–357 倍、快 5–350 倍"，且**两类判官错得一样**、85% 的 LLM 判决会重复决策模型的自信错误。这同时打中你的 RQ1（"能替代判官"）和 RQ4（"更便宜更快"），更打中任何"高置信放行 + 低置信升级 LLM"的防御设计。

**含义：不要写"Jev 能不能做安全判断/便宜不便宜"，要写"当 Jev 已经嵌进 Agent、且硬权限在模型外由确定性策略执行时，它的判断在什么接口和角色下、以什么代价，改变实际执行结果"。**

## 3. 五个结构性缺陷（不改，投稿会被打）

1. **没有基线。** 四条 RQ 只比较"用 Jev / 不用 Jev"。缺 (a) 确定性权限/污点检查，(b) 通用 LLM 判官，(c) 至少一个 AgentDojo 内建防御，(d) 无防御。缺 (a) 时"模型有效"不可识别；缺 (b) 时 RQ4 的成本无参照。2609.33401 自己在 §7 就建议"权限独立于模型判断强制执行"——你必须把这个建议**当作待检验假设**，而不是前提。
2. **RQ1 不可证伪。** "能胜任 / 边界"没有参照物和指标就不成命题。更麻烦的是：Jev 的"能力"不是模型属性而是**接口属性**——`state` 结构、`instructions`、`criteria`、候选集都由调用方定义（客户端确认：无 system prompt、无 temperature、一次请求一次前向）。同一模型换一种问法就是另一个系统。
3. **RQ2 把系统属性写成模型属性。** "维持正确的信任边界"的 gold 必须由 harness 的授权权威定义，而不是让模型自己理解授权再判它错（你自己在 pilot 协议里写对了这一点，RQ 没写）。否则审稿人一句"你的标签是作者自定的"就够。
4. **RQ3 的"分布变化"未定义。** 需要一份 shift 目录：攻击家族、注入通道/位置、suite/领域、语言、接口/选项集、模型版本/端点。每类迁移要能独立报告，否则"分布变化"是空话。
5. **RQ4 的反事实错位。** "引入 Jev 降低总体成本与延迟"默认 Jev 是**替代**昂贵组件；但若按门控串行接入，Jev 是**额外**开销。用你自己记录的数字算：Jev p50 1,067 ms vs 生成器代理 2.15 s/call，每个 episode 加 3–6 次 Jev 调用 = **+3.2–6.4 s，约 +19%–37% 生成时间**。所以"降低延迟"在加法式接入下不成立；只有在 selector 减少 prompt token/LLM 轮次、或 Jev 替代一个 LLM 自查步时才有机会。

## 4. 建议的 RQ 重构（保留四条，全部锚到同一条因果链）

统一场景：可执行 Agent（AgentDojo 固定版本）+ 硬权限在模型外由确定性策略执行 + 攻击者只控制指定通道。四条 RQ 是同一批 episode 的四种切法，不是四个实验。

> **RQ1（角色×决策点 → 执行后果）** 在可执行 Agent 中，把 Jev 放在哪类安全决策点、以什么角色接入（动作门控 / 上下文筛选 / 复核触发），会在多大程度上改变未授权执行率与合法任务完成率——相对于无检查、确定性策略、通用 LLM 判官？
> *预测*：语义授权点上有小而可测的收益；可规则化点无收益；selector 的收益主要来自 token/轮次而非安全。
> *反驳条件*：任一 Jev 配置在效用非劣（Δ≤5pp）下把越权率降低 ≥10pp（CI 排除 0）。

> **RQ2（信任边界机制）** 当外部文本改变其对"授权/证据"的声称（伪授权 vs 真授权、来源标签、论证强度、位置），Jev 是否把它当作决定性证据？概率输出是否暴露该错误（高置信错误率）？该错误是否传播为实际越权执行？
> *预测*：伪授权显著抬高放行（超过重跑噪声）；高置信错误占比不低，因此固定阈值不能单独构成安全边界。
> *反驳条件*：伪/真配对差异 ≤ 重跑噪声（|Δp|≤.05、翻转 ≤1%）且不产生执行级越权。

> **RQ3（冻结策略在迁移下是否守得住）** 在开发集上冻结策略（阈值 / 复核预算 / 子问题分解 / 确定性叠加 / 多模型 quorum），在未见攻击家族与分布迁移下，哪类策略能维持"风险—覆盖"约束？失效点在哪？置信度是否随错误升高（可检测预警）？
> *预测*：纯阈值策略在迁移下风险保证失效；置信度不随错误升高（severity 高）；分解+来源分层+确定性叠加在同一覆盖率下降低越权放行；单纯 escalation 纠正不了高置信错误（已有 85% 重复错误证据）。
> *反驳条件*：某一冻结策略在全部迁移下保持风险约束（CI 内）且效用非劣。

> **RQ4（安全买到了什么、代价多少）** 在匹配的（安全，效用）运行点上，Jev 组件的净成本与延迟是多少（现金、端到端中位/p95、复核与恢复成本）？在什么条件下优于替代方案（LLM 判官 / 确定性规则 / 无检查），break-even 在哪里？
> *预测*：现金成本可忽略；延迟净增（加法式接入）；只有替代式接入（selector 减 token、跳过 LLM 调用）可能净省，且被门控错误率与复核率抵消。
> *反驳条件*：匹配运行点上净成本与净延迟都低于替代方案（CI 排除 0），且不是靠漏检换来的。

配套：每条 RQ 预设指标、分母与"什么结果算支持/反驳"，在跑主实验前冻结（仓库里的 pilot 协议已经写好大部分，直接复用）。

## 5. 差异化轴：把 selector 提上来

门控方向已被打得最密；**"让快速决策模型决定 Agent 看到什么"几乎没人做**。2609.33401 只评"检索文本是否相关"（静态，61.0 vs 60.5 打平）；2610.02267 把它当静态门；没有人在闭环里研究筛选错误的安全后果。这条线自带三个论文级问题：

1. **选择投毒（selection poisoning）**：攻击者不改变文件内容，只让注入内容"看起来是完成任务所必需的证据"，从而**被选进来**，同时把限定条件/来源/警告**被选掉**。这是新的攻击面，且与"决策被翻转"不同。
2. **provenance stripping**：筛选器删掉"此段来自外部、不构成授权"的标注，等效于破坏信任边界——即使它没删任何其他内容。
3. **效用/成本不对称**：漏选一个必要 block 直接损害任务；多选一段只多花 token。这正好让 RQ4 从"加法开销"变成"净节省"，也让 RQ1 的角色比较有意义。

如果只保留一条主线，选这条：**"上下文选择作为 Agent 安全面"**，门控作为对照组。

## 7. 可行性硬约束（来自 feasibility-audit）

1. **闭环今天不存在。** AgentDojo 未安装（包缺失，本地只有 31 个 task-definition patch，引用未安装的 `agentdojo`）；唯一的"闭环"是相邻项目的脚本化模拟器（13 episodes、5 attacks、自评 grade C）。24 个候选任务**全部** `pending_manual_audit`，`injection_task_id / attack_payload / action_gold` 均 null。MVP 需 **14–22 人日**。
2. **样本量只支持大效应。** 配对 McNemar（α=.05 双侧、power=.8）：n≈97 只能检出 **12.6–19.9pp**（取决于不一致率）；n=24 只能检出 24.3–38.5pp；9 组比较做 Bonferroni 后 n=100 的检出下限升到 ≈19.5–22.5pp；按 4 个 suite 分组（每组 n≈24）只能检出 25–35pp。要声称"失败率 <1%"需要约 299 个独立观测（零失败单侧 95% 上界 1−0.05^(1/n)）。因此 RQ2/RQ3 必须按**大效应 + 明确上限**设计，或降级为探索性。
3. **成本与延迟的真实形状。** 1,200 episode-runs（100×3 攻击×4 配置）≈ 3,900 次 Jev 调用 ≈ **$0.17** 现金（高敏感情形 $1.24）；墙钟串行 7–11 h、8 并发 1.5–2.5 h。Jev 现金可忽略，**延迟不是**（+19%–37%/episode，加法式接入）。这直接决定 RQ4 的措辞。
4. **版本与可重复性。** 请求 `jev-1.13.0` 但记录到 `jev-1.13-free` 的情况已经发生过（jevout-40 baseline 与 manifest 不一致，且 `provider_equivalence_assumed: true` 未经检验）。同 payload 重跑 |Δp| 均值 .0097、最大 .05、1/33 动作翻转 → 阈值不能贴分数簇，种子 ≥3。价格 $0.042/M 只在文档里、且与 Microsoft-Decision-1 的价格数字相同，投稿前必须快照官方页面。
5. **单厂商风险。** 建议主表用官方 `jev-1.13.0`，另加 1 个本地快模型（`d3-mini` 4.54B / `decider-4b` / `Plumb-4B` 已在清单）做外部效度；至少回答"结论是否只属于 Jev"。

## 7.5 三种收缩方案（按投入排序）

- **方案 A｜完整 measurement paper**：四条 RQ 全部按 §4 重写，主实验 n≈97（或 60 语义授权集 + AgentDojo 两层），6 个 arm、2–3 个攻击、3 seeds。优点：故事完整；风险：广度大、每格样本薄，需要 4–6 周工程 + 大效应假设。
- **方案 B｜聚焦 selector（推荐）**：主问题 = 上下文选择作为安全面（选择投毒 / provenance stripping / token 与效用权衡），门控作为对照。RQ1 降为 §3 的角色对比表；RQ2 变成机制；RQ3 只对 selector 策略做迁移；RQ4 是真实净节省。优点：差异化最大、成本账最自然；风险：要自己造"必要/不必要/限定条件"的 block 级标签（可用 AgentDojo 工具返回 + 手工审核，约 12–20 对起步）。
- **方案 C｜最小可发表**：一份 workshop/短文：12–20 个审核任务、3 个 arm、1 个攻击、3 seeds（108–180 episodes，Jev 现金 <$0.10），只报大效应与明确上限，作为 A/B 的前置。优点：14–22 人日即可有真数据；风险：不能支撑 <10pp 或分组结论。

建议路径：先 C 拿真数据与方差估计，再按 B 扩成 full paper；A 只在"四条 RQ 都要独立成章"时采用。

## 8. 两周行动清单

1. 冻结 decision-point taxonomy（4–6 个安全相关决策点）+ 2 个角色 → 8–12 个接口；先做**离线** pilot（便宜、无需环境），确认问法/选项/标签可复核。
2. 钉 AgentDojo 版本并 smoke 一个 suite（B1），随后写 agent loop + model adapter + tool executor + gate/selector hook + episode 日志（B2）。
3. 审计 4 张任务卡（每 suite 一张）→ 扩到 12–20 对；写变体契约（伪授权/真授权/来源标签）与双人盲评（B3）。
4. 补账本字段：price 快照、generator latency、episode 级 token/延迟/重试/复核（B4）。
5. 用 20–30 episodes × 2 attacks × 3 arms 的 pilot 估方差 → 算功效 → 定主实验规模（或明确探索性上限）。
6. 预注册（OSF 或其他）：指标、分母、阈值选择规则、停止规则、反驳条件。
7. 先写 §2–§4（威胁模型/分类/指标）再写 RQ 段；RQ 段落最后定稿，因为 RQ 必须服从冻结的指标。
