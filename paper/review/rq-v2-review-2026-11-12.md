## 0. 结论

四条 RQ 的**模板是对的**（效果 / 效率 / 鲁棒 / 配置），比 10 月那版可执行得多，也与仓库现有的 12 模型 × 5 数据集矩阵对得上。但按今天的证据与文献状态，四条**当前的措辞**分别失败：

| RQ | 证据状态（你的仓库） | 文献状态（10-17→11-12） | 判定 |
|---|---|---|---|
| RQ1 判官有效性 | 只有组件级分类；全部 pilot；缺 9 个 cell | 每个粒度分别被占 | **不可用**（换轴后可救） |
| RQ2 效率与成本 | 只有描述性；比较性结论违反你自己的协议 | 端到端账本已被占 | **不可用**（须并入 RQ4） |
| RQ3 攻击下鲁棒 | 没有任何攻击实验 | 决策级鲁棒性已拥挤 | **不可用**（先做迁移版） |
| RQ4 配置影响 | 只有事后描述；无交叉设计 | 部分被占（边界/语言/顺序/批处理） | **可救**（但必须定义因子） |

同时，四条都绕开了你**唯一没被占据的资产**：五类检查位置（请求 / 外部内容 / 工具调用 / 动作前缀 / 回复）。
窗口内 29 篇论文中，**没有任何一篇**在同一个协议下比较 ≥4 个决策/guard 模型跨 input/action/trajectory 三种粒度
（最接近的是 peer-reviewed 的 2610.27620：9 个 LLM judge、per-action vs cross-execution 两个 scope）。
这就是论文该占的位置。

## 1. 已经发生的三件事（比 10 月更严重）

1. **"Jev 便宜"被端到端证伪。** 2610.24649（10-17，Terminal-Bench 2.1，21 任务/315 trials）：固定主 Agent，加 Jev 后
   每次尝试成本 **+19%**（95% CI 1.02–1.36），通过率 73.0% vs 73.0%；离线 AUROC 0.78，但 87% 通过的 run 里
   平均完成概率只有 0.50。→ 任何 "降低总成本" 的 RQ2 措辞都不能再写。
2. **"多模型/动作粒度/配置"被 2611.02155 拿走。** 11-01，22 个托管决策模型 + 2 个 prompt LLM，2,643 次工具调用、
   28 条规则、sealed holdout：显式边界使 recall +5.5–26.1pp（23 个可用模型全员）、Jev 1.14 89.3%→98.2%，
   中断率 30.6%→4.8%，**120 ms、$0.46/1k**。→ "多模型 × 预执行 × 配置" 的卖点已经不属于你。
3. **"决策模型 vs LLM 判官"被 2611.00505 拿走。** 14 个 System-1 模型 vs 4 个生成式判官、11 个判官基准：
   5 个与 GPT-5.6-no-reasoning 统计不可区分；与 reasoning 同级时成本约 **1/16**；注入 note 翻转 0–5% vs 17–49%；
   排行榜预测准确率 r=0.95–0.96。→ RQ1/RQ2/RQ3 的"比较新颖性"全部消失。

另有 2611.03759 JevBreak（7 模型、32–99% ASR、17–72 queries）、2610.38895 FlipJev（universal suffix 43%/90–100%）、
2611.02522（置信度监控漏 51–70%，若 note 声称确定则 99–100%）、2611.08229（300 queries 内 43% 绕过）、
2610.36311（point-estimate 阈值在 147/190 次评估中背离承诺，Learn-then-Test 0/190）、2610.34329（SHIFT-Jev 10 环境）、
2610.37688（语言阈值差 8.6–11.7pp）、2611.06384/2611.09803（位置/顺序效应）、2611.12521（打包问题翻转 11.7–22.4%）。

## 2. 逐条判词

### RQ1 "How effective are System One models as security judges for LLM agents?"
- **用词错。** 12 个 arm 是 6 个 typed decision model + 3 个 guard classifier + 3 个生成式 LLM 判官（仓库选型文档自己的
  类别列可证）。叫 "System One models" 只覆盖 5/12；而且该 umbrella 已被 2611.00505/2610.33775 占用。
- **"for LLM agents" 超范围。** 全部 209 个派生分组 `episode_results.scorable=0`，无 `traces/`；没有一次 Agent 执行。
  你自己的草稿（main.tex:36）就写了隔离分类"cannot determine which outcome occurs during execution"。
- **接口混淆。** native guard template / System One choice / strict JSON boolean 三种输入输出合同不同
  （operations §4 明确"不能声称它们接收了同样的任务指令"）。单一排名比较的是接口，不是判官质量。
- **可救的部分**：把 "effectiveness" 变成**位置条件**的判别力与错误方向，并把接口作为显式因子。

### RQ2 "How do System One models perform in terms of runtime efficiency and cost...?"
- **不是研究问题。** 延迟/费用是测量维度；没有参照系（相对谁？每判定还是每 episode？）。
- **不可比。** 9/12 是本地模型、按你协议"本地计算未计价"；3 个 API 只有 list-price 估算（非账单）；GPU 4GB vs 12GB、
  OpenLux vs Packy、VPN vs 直连、每 item 调用次数不同。把它做成跨模型成本排名违反协议第 4 节。
- **方向也被证伪**：2610.24649 显示加入 Jev 后端到端成本 +19%。成本问题只能是"每 episode 付多少、买到了什么风险下降"。
- **唯一有结构价值的事实**：prefix monitoring 是 O(steps)。StepShield 最多 83,194 次判定/模型，而 AgentHarm 416 条。
  "每次判定便宜" ≠ "每任务便宜"，这正是可发表的成本结构结论。

### RQ3 "How robust are the security judgments of System One models under attack?"
- **目前没有实验。** 12 模型 × 5 数据集上没有任何扰动/自适应攻击 run；只有历史 JevOut 的 Jev 1.13/MMLU-Pro 小 pilot
  （2/32，语义有效性未确认）。InjecAgent/AgentHarm 的"攻击"是判官要抓的阳性，不是对判官的攻击。
- **文献已拥挤**（见 §1）。而且 2610.27620 已证明 per-action 授权在关系型违规上不 composable（2-safety），
  这直接质疑"逐步监控"的前提——你必须引用它，而不是绕开。
- **可立即执行的替代**：用原生迁移 split 做"冻结操作点的稳定性"——AgentHarm validation vs test_public、
  InjecAgent base vs enhanced、StepShield test vs test_holdout、TS-Bench 三个来源域。
  无需新攻击 run；先把 `severity`（漏检时的置信度）与覆盖一起报（模板见 2606.22659）。

### RQ4 "How do different configurations affect the performance...?"
- **"configurations" 至少有四种读法**：检查位置、模型类别、提示/接口、阈值/后处理。不定义就无法证伪。
- **与 RQ1/RQ2 重叠**：效果本身随配置变化；成本也随配置变化。
- **最有价值的读法**：**接口 vs 模型 vs 位置的方差分解**。你仓库里已有 10 类实际变化的因子（位置、模型类别、
  包装、输出合同、阈值、重复、重试、provider、硬件、Jev type 仅 choice），但没有一个是受控交叉的。
  文献里只有零散单因子（边界 +5.5–26.1pp、语言、顺序、打包、批处理），**没有位置 × 接口 × 模型的交叉设计**。

## 3. 你的资产：五类检查位置

| 位置 | 基准 | 全集 n | gold / 主要指标 | 每 episode 判定数 |
|---|---|---|---:|---:|
| User Request Inspection | AgentHarm | 416（208/208） | 输入有害性二分类 | 1 |
| External Content Inspection | InjecAgent | 2,108（全正例，无负类） | 注入检出率（无 FPR） | 1 |
| Tool Call Inspection | TS-Bench | 7,182（safe 3,770 / unsafe 1,631 / unknown 1,781） | 执行前动作安全 | 1 |
| Action Inspection | StepShield | 8,151 轨迹（747 rogue） | EIR(k)、IG、首警步、轨迹混淆矩阵 | O(steps)，最多 83,194 |
| Response Inspection | WildGuardTest-E | 1,725（284/1,425/16） | response_harm 二分类 | 1 |

这条轴有三个别人没有的性质：
1. **错误代价随位置变化**：越往后，漏检越接近不可逆（放行一个工具调用 vs 事后发现回复有害），误拦的代价越低。
2. **可见信息随位置变化**：请求 → 外部内容 → 历史+候选动作 → 已观察前缀 → prompt+回复。
3. **成本随位置变化**：O(1) vs O(steps)，差 200 倍。

→ 论文的核心命题可以写成：**"判官的可委托性由检查位置决定，而不是由模型身份决定；冻结的操作点必须按位置分别选择。"**

## 4. 建议改写的四条 RQ（保留编号与顺序感，换轴）

> **RQ1（位置条件效果）** 在五个检查位置上，12 种判官配置的判别力与错误方向如何变化？模型排名是否随位置改变？
> *统计量*：位置间 Kendall τ（排名稳定性）、按内容族聚类的 bootstrap CI。**不**比较跨位置的绝对 accuracy
> （基率与 gold 不同，不可比）；比较排名与错误方向。
> *预测*：τ < 0.7，位置解释的方差 > 模型类别。*反驳*：τ ≥ 0.7 且模型类别占主导。

> **RQ2（操作点与错误不对称）** 每个位置上可辩护的 (FNR, FPR) 前沿是什么？漏检/误拦的代价比如何随位置变化？
> *指标*：固定误报预算下的 TPR、fail-open 率、置信度在漏检上的位置（severity）、覆盖与未决数。
> *预测*：越靠后，最优操作点越偏保守（更低 FPR、允许更高 FNR），且"高置信漏检"比例越高。
> *反驳*：五个位置的最优操作点在同一 (FNR, FPR) 区域，且置信度在漏检上与命中上无差异。

> **RQ3（冻结操作点的迁移稳定性）** 在原生迁移切分下（base→enhanced、validation→test_public、test→holdout、
> 三个来源域），冻结的操作点是否守住风险/覆盖约束？置信度是否随错误升高？
> *预测*：守卫类与通用 LLM 的位置效应不同；point-estimate 阈值在迁移下失效（已有 2610.36311 的 147/190），
> 置信度不能单独作预警。*反驳*：所有位置在全部迁移下保持约束且 severity 低。

> **RQ4（成本结构与配置交互）** 每 episode 的成本/延迟如何随位置变化（O(1) vs O(steps)），API 与本地两条轨道如何分列？
> 接口（type/criteria/state 序列化）与模型、位置相比，各解释多少性能方差？
> *预测*：现金成本在 prefix 位置主导；接口因素的解释力不亚于模型类别；便宜 ≠ 每任务便宜。
> *反驳*：模型类别解释 >70% 方差，且每 episode 成本与位置无关。

这四条全部锚在你已有的五个位置上；RQ2/RQ3 的第一版**不需要新攻击实验**；RQ4 的接口消融只需 Jev-only 的小规模
（2 个位置 × 3 type × criteria 两档 ≈ 数千次调用）。

## 5. 在写 RQ 之前必须先解决的 8 件事

1. **冻结**：209 个分组全是 `phase=pilot`；full campaign 的 `confirmation_protocol_manifest=null`；
   decisions.md 停在 11-05。先写 freeze manifest（样本、阈值、重试、预算、停止规则），否则任何数字都只能是描述性。
2. **执行或降级标题**：零 Agent loop。要么加一个小闭环（A/J/L/R 的 20–40 episode pilot），要么标题/摘要明确
   "judge-level, in agent pipelines"，删掉"for LLM agents 的防护"暗示。
3. **类别分开报**：6 决策模型 / 3 guard / 3 生成式；接口差异作为因子，不强行单排名。
4. **标签语义不可合并**：InjecAgent 全正例（TN=FP=0，"accuracy"=recall）；TS-Bench 25% unknown 且按来源差异剔除
   （57%/72%/100%）；AgentHarm 是输入分类不是官方 harm score；ATBench 只有 n=2 smoke → 补跑或删掉 D。
5. **聚类**：AgentHarm 416 条 52 族；TS 7,182 步 3,376 族；StepShield 8,143 族。所有区间按族聚类
   bootstrap；"3 repeats" 不是 3 个样本。
6. **样本代表性**：50 条 pilot 的 GLiGuard .980 → test_public .741；pilot 排名不可外推。
7. **成本轨道**：API（账单或 list-price 快照）与本地（GPU·小时，明确假设）分开；unknown 不填 0；
   per-call 与 per-episode 都报；Jev 的 OpenLux pilot 与 Packy full 之间需要同一样本桥接（且 1.13 vs 1.14 未桥接）。
8. **补齐矩阵或明确删格**：TS-Bench 8 个本地模型 + Jev-Guard；StepShield 12 模型且修好 report.py
   （Jev 8,151 episodes 已跑完但无 analysis）；WildGuard E 其余 11 个；ATBench 见 4。
