Abstract
 

Security workflows need models that turn complex observations and explicit policies into decisions. System One models introduced by Jev return typed predictions and probabilities; security specialization supplies the domain expertise behind those predictions. We introduce SecJev, to our knowledge the first family of Jev-style decision models specialized for security, spanning 0.8B to 9B parameters. Built on Kev’s single-pass candidate scorer, SecJev learns Boolean, choice, and ordered decisions from text, telemetry, and observation histories. We develop SecJev-Corpus to unify source-label prediction and explicit-policy evaluation across 14 tasks and eight sources. It covers tool outputs, traffic, federated updates, consensus, authentication, and vehicle messages. Scene-weighted training adapts the models across these domains while preserving a shared typed decision interface. Security specialization improves every model in the family; SecJev-0.8B outperforms general Kev-9B by 20.51 percentage points in task-macro accuracy. At 0.8B and 4B, SecJev achieves accuracy and latency close to answer-only generative fine-tuning with lower peak allocated GPU memory. SecJev-4B improves on Kev-4B and security-trained generation in prompt-injection and traffic transfer tests. We release adapters, decision heads, SecJev-Corpus, and training and inference code.
 







1 Introduction



Security workflows repeatedly turn complex observations into decisions about tool outputs, authentication histories, or voting evidence (Debenedetti et al., 2024; Kent, 2016; Bano et al., 2022). The same tool response can require both injection detection and a trust-boundary action, while voting evidence can require both a quorum judgment and a policy decision. Each answer depends on how the observation relates to the question and any applicable policy.


Figure 1: SecJev’s shared decision path and security adaptation. Source annotations and explicit policies provide requests and targets. One backbone with layerwise LoRA adapters produces decision-marker and candidate-end states; the pointer head scores candidates to obtain typed outputs. Solid edges carry forward computation during both training and inference. Gray dashed edges supply gold labels and logits to scene-weighted cross-entropy; coral dashed edges update only LoRA and the head, leaving the backbone frozen. General-decision initialization uses official Kev for 0.8B/4B/9B and our pretrained 2B model.



Jev introduced System One models in September 2026 that return typed decisions and probabilities directly (Almeida, 2026). Kev provides open weights for training and running Jev-style models (Palmer, 2026). Here, Jev-style denotes models that take observations, a question, and candidate meanings as input and return probabilities over Boolean, choice, or ordered alternatives. Security specialization equips this general decision interface with the expertise to interpret domain observations and apply stated policies.



We introduce SecJev, to our knowledge the first family of Jev-style models specialized for security, at 0.8B, 2B, 4B, and 9B. SecJev brings security expertise to Kev’s single-pass candidate scorer through trained adapters and a decision head. All four models support Boolean, choice, and ordered outputs, allowing distinct questions about a scene to share the same model and typed interface.



We develop SecJev-Corpus to train this capability across tool outputs, traffic, federated updates, consensus, authentication, and vehicle messages. Its 170,185 questions combine source-annotation prediction from observations with explicit-policy evaluation against visible evidence. Questions and candidate descriptions preserve the target semantics of each task. Scene-weighted training balances scenes with different numbers of questions while retaining the single-pass decision path (Figure 1).



Security specialization improves all 14 tasks at all four sizes. SecJev-0.8B gains 39.40 percentage points in task-macro accuracy over Kev-0.8B and exceeds general Kev-9B by 20.51 points. At 0.8B and 4B, SecJev combines accuracy and latency close to answer-only generation with lower peak allocated GPU memory. General-decision initialization improves the 0.8B model over training the pointer directly on Qwen3.5. Four-shot BIPIA and IoT-23 tests extend the gains to related security tasks. Paraphrase and candidate-permutation tests show stable task aggregates, while general-task evaluation measures capability retention. We release the models, SecJev-Corpus, and code.




2 Related Work



Domain and security specialization.



Domain-adaptive pretraining and instruction tuning focus language models on specialized distributions (Gururangan et al., 2020; Wadden et al., 2025; Shi et al., 2025; Zeng et al., 2024). CyberBench combines a multitask cybersecurity benchmark with CyberInstruct, a family of security instruction-tuned generative models (Liu et al., 2024). SecBench evaluates security knowledge and reasoning through multiple-choice and short-answer questions (Jing et al., 2024). LLM fine-tuning also supports anomaly detection in behavior logs (Song et al., 2025). SecJev develops a security-specialized Jev-style family whose shared scorer conditions on the observation, question, and candidate meanings. This supports both source-label prediction and explicit-policy decisions across security domains.




Decision interfaces.



Jev introduced typed System One predictions (Almeida, 2026); Kev supplies the pointer head and Boolean, choice, and ordered-score interfaces used here (Palmer, 2026). SecJev specializes this architecture through low-rank adaptation (LoRA) (Hu et al., 2022), with temperature scaling for confidence (Guo et al., 2017). Prompt-injection attacks on Jev motivate evaluating how decision models interpret security evidence (Wu and Lim, 2026). Classification-head fine-tuning also provides discriminative multiple-choice decisions, scoring each context–candidate sequence separately (Sood and Savelka, 2026). SecJev brings security specialization to Jev-style models with a shared single-pass candidate scorer, and compares the family with one-token generation and candidate-sequence classification.




Security observations and policies.



AgentDojo and InjecAgent provide tool-integrated injection scenarios (Debenedetti et al., 2024; Zhan et al., 2024). CICIoT2023, ToN-IoT, LANL, and VeReMi supply network, authentication, and vehicle observations (Neto et al., 2023; Moustafa, 2021a; Kent, 2015; Hermann et al., 2026). Twins and ByzFL support controlled consensus and federated-learning scenarios (Bano et al., 2022; González et al., 2025). SecJev-Corpus preserves their target semantics while expressing questions and candidate meanings through one interface.





3 SecJev



3.1 Decision Interface



A scene contains a state ss and one or more questions. Each question supplies an instruction qq and candidate descriptions C=(c1,…,cK)C=(c_{1},\ldots,c_{K}). The state holds text, telemetry, or an observation history, including any policy required by the question. A Boolean request returns the probability of true; a choice returns candidate probabilities and the highest-scoring key; an ordered request additionally returns the expected level. Candidate descriptions are inputs, allowing one head to support different answer vocabularies.



Kev renders each question as an independent causal row containing the state, question, delimited candidates, and a final decision marker, preserving field names and order. This accommodates Qwen3.5’s hybrid recurrent and attention backbone (Qwen Team, 2026). Batches contain independently encoded questions, with candidate order visible within each row.

3.3 Security Adaptation



The 0.8B, 4B, and 9B models inherit released Kev adapters and heads. The 2B model first learns general decisions on Qwen3.5-2B-Base using Kev’s general-decision data and a supplement covering date reasoning and missing evidence. All four use a three-epoch security-training budget.



We freeze the backbone and train rank-16 LoRA adapters with scaling factor 32 and dropout 0.05, together with the pointer head. Adapters cover attention, feed-forward, and DeltaNet projections. Every security question appears once per epoch, without general-domain replay. To balance scenes containing different numbers of questions, question jj in scene ii receives weight 1/mi1/m_{i}. For NN scenes, the objective is

(3)


All output types share this candidate cross-entropy objective.



A separate calibration split fits one positive scalar temperature by minimizing negative log-likelihood (NLL). Scaling changes confidence while preserving the highest-scoring candidate. Appendix A.1 specifies checkpoint selection and Appendix A gives the training details.

The ordered task concerns consensus evidence, where each level has an explicit meaning. Construction follows two target families: source-annotation prediction from observations, and policy evaluation from a displayed rule and history. 4.1 Task Construction



Tool-output security.



AgentDojo scenes preserve the trusted request, tool call, untrusted response, and trust policy. Questions ask whether an embedded injection is present and whether the response should be used as data or its redirecting instruction excluded. InjecAgent questions distinguish instructions requesting information transfer from other operations. The target describes the requested operation, not attack success or the sensitivity of every transmitted item. A detection formulation with only positive labels is excluded.




Traffic and vehicle observations.



CICIoT2023 predicts attack-capture labels from measured traffic. ToN-IoT predicts connection labels from protocol and application telemetry, omitting endpoint identities. VeReMi uses local vehicle-message histories to predict the final message’s manipulation label and one of ten attack/normal categories. These tasks predict the original source annotations from the displayed observations.




Client updates and voting.



ByzFL-based supervision comes from 80 controlled MNIST experiments. Inputs contain measured update magnitudes, median distances, and historical cosine similarities, informed by FoolsGold (Fung et al., 2020). Labels distinguish attack-generated updates from honest local training, including non-IID clients. Twins scenes show received messages, a candidate block and round, validators, and a quorum threshold. Questions address visible conflict, quorum, certificate action, and evidence level. The stated policy rejects an observed conflicting voter, otherwise accepts a quorum, and otherwise waits. The targets therefore describe the received evidence and its policy consequences.




Authentication policies.



LANL scenes use the current event and a source account/computer’s preceding 300-second history (Kent, 2016). Same-second events are excluded because their ordering is unknown. Questions concern a prior-failure threshold and a stated logon-triage policy. This is post-event triage: the current success/failure may be visible. This supplies policy-defined supervision for events without attack annotations.





4.2 Splits and Quality Control



Records separate visible evidence from labels and provenance. Source labels map to semantic candidates; policy answers are computed from the displayed rule and history. Identifiers are locally aliased without breaking relationships. Questions are added only when the source supports the corresponding distinction.



Table 2 gives the four splits. All questions from a scene remain together. Grouping uses captures for CICIoT2023, source hosts for ToN-IoT, simulation runs for Twins/ByzFL, and chronological days for LANL. AgentDojo groups link records sharing normalized tool responses; InjecAgent groups records by trusted user task. VeReMi retains its independent test boundary and groups related non-test vehicle observations. Every semantic class has at least 50 questions per task/split; no class exceeds 80%, and the largest cross-split class-share gap is 8.58 percentage points. Unordered correct-answer positions are distributed within classes and splits; ordered levels retain their order.

5 Experiments



We evaluate security capability across sizes, accuracy and inference cost against generation, and transfer to related sources. Analyses examine initialization, semantic consistency, and general-decision retention.



5.1 Experimental Setup



Evaluation.



We evaluate all 21,634 security-test questions. Task-macro accuracy gives each of the 14 tasks equal weight; micro accuracy weights individual questions. Task-macro balanced accuracy additionally averages class recall within each task. All three output types use their highest-probability candidate for accuracy. A majority baseline selects each task’s most frequent training semantic class, independent of answer position. Paired 95% intervals use 2,000 source-stratified bootstrap draws of whole groups, sharing group weights across associated tasks (Appendix E).




Training and precision.



Security adaptation uses AdamW and rank-16 LoRA. Peak learning rates are 2×10−52\times 10^{-5} for the first epoch and 10−510^{-5} for continuation, with effective batches of 128 and 192. Security-test accuracy uses 32-bit floating-point (FP32) backbones for 0.8B/2B/4B and bfloat16 (BF16) for 9B, with FP32 adapters and heads. Each parent–SecJev pair uses matching precision and complete inputs. Appendix A gives the optimizer and schedule details.

Security specialization produces gains throughout the family, with 4B leading task-macro accuracy (94.51%) and balanced macro (92.42%). The capability profile spans three settings: at 4B, task-macro accuracy rises from 63.38 to 99.30% on the three tool-text tasks, from 50.53 to 85.19% on the five source-label tasks, and from 84.58 to 99.87% on the six explicit-policy tasks. 5.3 Comparison with Other Decision Interfaces



SecGen is the generative supervised fine-tuning (SFT) baseline on SecJev-Corpus at 0.8B and 4B, using matching Qwen3.5 bases, rank-16 LoRA, scene weighting, and three epochs. It predicts one answer-key token with full-vocabulary cross-entropy and a frozen vocabulary head. At 0.8B, we also train a shared scalar classification head on separately encoded context–candidate sequences (Sood and Savelka, 2026), using the same security recipe. A direct-Qwen pointer measures candidate scoring without Kev initialization. Appendix F gives protocols and development-based selection.



Timing uses one RTX 3090, a common BF16 backbone with FP32 adapters and heads, and matching attention implementations. Accuracy is recomputed on the full security test with the serial timing implementation for Table 4. Batch-one latency includes request parsing and validation, tokenization, device transfer, inference, and answer processing after warm-up, excluding model loading. Each request contains one question, with no prompt-cache reuse. Short inputs have at most 512 tokens and long inputs have 2,048–8,192; each stratum contains 100 fixed development questions. Greedy generative decoding uses an answer-key grammar and stops at key completion. Invalid outputs count as errors. We evaluate transfer to BIPIA-derived prompt-injection detection22

Each dataset contains 1,000 binary test examples, with 500 examples per class. All three 4B models use 4-shot prompts with four labeled demonstrations retrieved from a pool disjoint from the test sets. The demonstrations specify source-specific label meanings and decision criteria, providing a compact way to configure a new security task. Model parameters remain fixed.



On BIPIA, SecJev-4B reaches 83.60% accuracy, exceeding Kev-4B’s 71.30% and SecGen-4B’s 79.60% by 12.30 and 4.00 percentage points (Table 5). SecJev combines 99.80% recall with 75.38% precision. Its false-positive rate falls to 32.60%, from 54.00% for Kev and 39.60% for SecGen. In this test, SecJev combines higher injection recall with fewer false alarms.



On IoT-23, SecJev-4B achieves 90.20% accuracy, versus 73.00% for Kev-4B and 84.30% for SecGen-4B, gaining 17.20 and 5.90 points. Precision rises to 86.95%, and the false-positive rate falls to 14.20%, versus SecGen’s 76.34% and 30.80%. SecGen has higher recall (99.40% versus 94.60%), while SecJev’s fewer benign-flow errors yield higher overall accuracy. SecJev leads both baselines across the two tasks under this four-example setup. These gains support using one security-specialized decision interface for both untrusted text and structured traffic observations.





6 Analysis



6.1 Question Meaning and Candidate Order



A shared decision model should track question and candidate meanings across equivalent formulations. We test paraphrased questions and permuted unordered alternatives, keeping evidence, field order, rules, and semantic labels fixed. We use 100 test questions per task, each paraphrased once (1,400 pairs). Each of 100 questions from five choice tasks also receives one nonidentity permutation (500 pairs); ordered levels are not shuffled. Together with the originals, this yields 3,300 requests per model. Predictions are mapped back to semantic keys.



In Table 6, paraphrasing reduces accuracy by 0.07–0.93 percentage points across all four sizes, while permutation changes it by −0.80-0.80 to +0.40+0.40 points. Answer agreement is 95.36–98.36% for paraphrases and 97.40–98.80% for permutations. Both-correct scores separate preserved correct decisions from stable mistakes. Aggregate accuracy is stable across the tested formulations; paired agreement measures which individual decisions persist.



Task-level results separate aggregate stability from changes in individual decisions. For 0.8B, paraphrasing reduces federated-update accuracy from 91% to 85% and vehicle attack-type accuracy from 39% to 32%. For 9B, ToN-IoT falls from 95% to 89%, while CICIoT rises from 88% to 95%; these offsetting shifts yield a net loss of just one answer. Across sizes, 15–38 previously correct answers become incorrect among the 1,400 paraphrase pairs. For 9B VeReMi manipulation, prediction agreement is 77%, with a one-point accuracy change. Fixed-batch controls are discussed in Appendix C.




6.2 Value of General Decision Initialization



The 0.8B comparison fixes the backbone, pointer architecture, security data, and three-epoch budget. One model inherits Kev’s adapters and head; the other learns these components directly on Qwen3.5. Development selection favors epoch 3 for both. Kev initialization reaches 90.34% test macro accuracy versus 88.17% for direct-Qwen training, a 2.17-point gain; balanced macro rises from 83.75% to 88.00% (Table 7). Direct-Qwen training performs better on AgentDojo boundary actions and federated-update classification, while Kev initialization yields its largest gains on vehicle manipulation and attack type (Appendix D). Overall, general-decision initialization provides a stronger starting point for security adaptation under the fixed training budget.

6.4 Data Validity and Supervision Semantics



Exhaustive checks find no schema or candidate-label violations in 170,185 questions and no disagreement in 37,490 independently recomputed policy answers. Two human reviewers independently assess 280 questions, 20 per task, and agree on 261 answers (93.21%). Both match the corpus labels on all 180 tool-text and explicit-policy questions. On the 100 source-label questions, they agree on 81 answers and both rate the visible evidence as sufficient for 28. The review supports the interpretability of tool and policy supervision, while locating the main uncertainty in inferring source annotations from partial observations (Appendix B).





7 Conclusion



SecJev brings security expertise to System One decision models through four Jev-style models with a shared typed interface. Training across 14 tasks improves every model and enables SecJev-0.8B to outperform general Kev-9B. SecJev-Corpus combines source-label prediction and explicit-policy evaluation. The 0.8B and 4B models achieve accuracy close to answer-only generation with lower peak allocated GPU memory. SecJev-4B also improves transfer accuracy on BIPIA and IoT-23. General decision initialization also strengthens the 0.8B model beyond security-only training. Question-conditioned scoring lets one model express distinct judgments about the same evidence through a shared security-trained head. SecJev-Corpus provides the security supervision connecting these judgments to source annotations and explicit policy rules. We release SecJev, SecJev-Corpus, and code for security-specialized System One models.





Limitations



SecJev evaluates finite decisions over supplied observations. Capture and experiment annotations can depend on information outside an individual input, so those tasks measure source-label prediction. Policy tasks measure application of the displayed rule. End-to-end attack prevention and autonomous response require separate deployment evaluation.



The 14 tasks have uneven difficulty: near-perfect policy scores coexist with lower vehicle-message accuracy. Task-macro averages weight these tasks equally. Recorded group boundaries address specific dependencies; residual semantic overlap and transfer beyond the tested sources remain open. Human review concentrates answer disagreements in source-label tasks, where visible telemetry provides incomplete evidence about the source annotation.




Ethical Considerations



The corpus includes attack-bearing text and security observations for research on defensive decisions. Local aliases preserve within-scene relationships while reducing unnecessary identifiers. We retain source attribution and source-specific usage conditions rather than assigning a blanket permissive license to all underlying data. Model predictions and calibrated probabilities are fallible, particularly when evidence is incomplete; consequential actions require an application-specific policy and evaluation.

Appendix A Implementation and Model Selection



Training runs span three security epochs and 118,818 questions per epoch. We train one run per condition. AdamW uses weight decay 0.01 and gradient clipping at 1.0. The first epoch and the two-epoch continuation each use a 5% warm-up followed by cosine decay to one tenth of their respective peak learning rates; optimizer states continue across epochs. The effective batches correspond to 929 updates in epoch 1 and 619 updates in each continuation epoch, totaling 2,167 updates and 356,454 question presentations. The reported 9B epoch-2 checkpoint has 1,548 updates and 237,636 question presentations. No security evidence is truncated to fit the 8,192-token limit. The 9B run keeps the frozen backbone in BF16 and its adapters, decision head, and optimizer states in FP32; the smaller runs use FP32 master weights with BF16 autocast during training. Evaluation precision follows Section 5.1.



The 2B initialization is trained on Kev’s general-decision training split (upstream decision-v7), with the date-reasoning and missing-evidence supplement. Official Kev initializations are used at 0.8B, 4B, and 9B. The direct-Qwen control starts without this general decision stage.



A.1 Model Selection



The 0.8B, 2B, and 4B models use epoch 3, selected by development task-macro balanced accuracy over semantic classes. The reported 9B model uses epoch 2.

Appendix F Generative and Classification Baselines



SecGen-0.8B and SecGen-4B start from Qwen3.5 and train rank-16 LoRA adapters on the same 118,818 security questions for three epochs, each totaling 356,454 question presentations and 2,167 updates. The original backbone and vocabulary head are frozen. Training retains FP32 weights and optimizer states with BF16 autocast; development, calibration, and test inference use FP32 throughout, without TF32, at batch size one. Supervision is full-vocabulary cross-entropy on one answer-key token, weighted by the inverse number of questions in its scene. Decoding selects the highest-scoring valid key and ends after that token. For these one-token keys, ranking their vocabulary log-probabilities is identical to constrained greedy selection.



The 0.8B candidate-sequence classifier adapts Sood and Savelka (2026): each state and question is concatenated with one candidate, and its final nonpadding hidden state is mapped to a scalar by a shared bias-free linear head. Cross-entropy normalizes these scores across the question’s candidates. Starting from Qwen3.5-0.8B-Base, we train the fresh head and rank-16 LoRA adapters with the same security data, scene weighting, optimizer schedule, and three-epoch budget as the other Qwen controls. Training uses BF16 autocast with FP32 master parameters; evaluation is FP32 without TF32. The three epochs take 8.75 hours on nine RTX 3090s. This comparison evaluates a candidate-conditioned encoding interface, which repeats the context for each option, alongside SecJev’s shared encoding of all candidates.



Each epoch is evaluated on all 14,912 development questions. Semantic-class balanced macro selects epoch 3 for SecGen at both sizes (Table 16); ties select the earlier epoch. Temperatures of 1.466 and 1.264 for 0.8B and 4B are fitted to candidate-normalized NLL on 14,821 calibration questions, before evaluating the 21,634 test questions. At both sizes, the unconstrained vocabulary argmax is a valid answer key for every test question. For classification, full-development semantic-class balanced macro selects epoch 3; the same calibration split gives a single global temperature of 1.288.

Appendix G Matched-Precision Timing Details



An answer is complete when the final structured decision is available to the caller. Timing includes tokenization and output parsing, and excludes model loading. All six models run serially on the same RTX 3090 with Python 3.11.11, PyTorch 2.6.0, CUDA 12.6, Transformers 5.17.0, PEFT 0.21.0, and NVIDIA driver 570.133.20. Both interfaces use scaled dot-product attention (SDPA). Backbone weights are BF16; original FP32 adapter and output-head values are retained. Full-test accuracy is recomputed serially at batch size one on all 21,634 questions per model (Table 19). The Kev-9B scores in Table 3 use its original three-shard batched evaluation. Balanced macro groups gold answers by semantic label, not by their displayed position.



The fixed timing workload contains 200 development questions from distinct scenes, selected by hash order and task round-robin without predictions or labels. Length limits hold for every method. The 100 short requests span 11 tasks; the long stratum contains 34 ByzFL and 33 questions from each LANL task. Thus length-stratum results also reflect different task composition. Each pass uses the same requests in a shuffled order with seed 20260929+r20260929+r, for pass r=0,…,4r=0,\ldots,4, following two warm-up requests per stratum. Timed predictions are not used for model selection.



Table 20 gives the range of per-pass medians and the mean and sample standard deviation of serial batch-one throughput. In each pass, throughput is 200/∑i=1200ti200/\sum_{i=1}^{200}t_{i}, where tit_{i} is the measured request time in seconds. The fixed workload contains equal numbers of short and long requests; throughput therefore differs from the reciprocal of either stratum median. All six models complete five serial batch-one passes.
